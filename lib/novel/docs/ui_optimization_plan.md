# 小说模块扩展界面优化方案

## 一、现状分析

### 当前页面结构

```
NovelListPage (首页)
├── _buildCompactHeader()    ← 书源标签 + 搜索状态标签 + 刷新按钮
├── _buildSearchBar()        ← 搜索输入框 + 搜索/取消按钮
├── _buildExploreBar()       ← 横向滚动的发现页标签栏
├── ErrorBanner (条件显示)
└── Expanded(RefreshIndicator)
    └── NovelBookCard × N

BookSourceManagerPage (书源管理)
├── BookSourceManagerHero    ← 统计卡片 (全部/启用/匹配)
├── BookSourceStartupBanner  ← 启动消息横幅
├── BookSourceQuickActions   ← 导入/新增/导出 三个 ActionCard
├── BookSourceSearchBox      ← 搜索框
└── ListView: BookSourceCard × N
    └── 7 个按钮 (启用/诊断/编辑/测试/导出/查看/删除)
```

### 存在的问题

1. **列表页头部信息密度过低** — 只有书源名标签+刷新按钮，缺少统计信息和快捷操作
2. **发现页（Explore）功能薄弱** — 只有简单横向标签栏，没有分组/分类展示
3. **书源管理页按钮过多** — 每个 BookSourceCard 有 7 个按钮，手机上无法完整显示
4. **缺少全局统计面板** — 用户不知道有多少书源、多少书籍、缓存占用
5. **搜索结果页无排序/筛选** — 只能按搜索顺序浏览，无法按作者/状态/字数排序
6. **缓存管理缺失** — 无法查看/清除缓存，无法设置缓存策略
7. **书源管理缺少分组/标签** — 大量书源时难以管理
8. **阅读器入口单一** — 只能从卡片点击进入详情页再进阅读器

---

## 二、优化方案

### 🟢 Phase 1: 列表页增强（高收益、低风险）

#### 1.1 增强 Header — 增加统计信息条

在紧凑头部下方增加一行统计指标：
```
📚 书源: 3 | 📖 书籍: 128 | 💾 缓存: 45MB | 🔍 发现: 分类
```

- 点击 "书源" → 弹出书源切换列表
- 点击 "书籍" → 显示最近阅读/书架统计
- 点击 "缓存" → 弹出缓存管理（清除缓存/查看大小）
- 点击 "发现" → 展开分类面板

#### 1.2 发现页增强 — 分组卡片式展示

当前发现页只是简单的横向标签，改为：
- 如果 exploreUrl 是 JSON 数组格式，解析为分组结构
- 使用 `SliverGrid` 或 `ExpansionTile` 展示分组+子项
- 支持折叠/展开，避免长列表

#### 1.3 搜索结果排序/筛选

在搜索模式下，搜索栏右侧增加：
- **排序按钮**：按相关性/书名/作者/更新时间排序
- **筛选按钮**：按状态(连载/完结)/分类/字数范围筛选

---

### 🟡 Phase 2: 书源管理页重构（中等收益、中等风险）

#### 2.1 书源卡片改为列表行

当前 `BookSourceCard` 是一个展开的大卡片，7 个按钮在手机上一行放不下。
改为两态设计：

**折叠态（默认）** — 每行显示：
```
[开关] 书源名称        当前使用 ●    已启用 ✓    可用 ●
       https://api.xxx.com
```

**展开态（点击行）** — 显示详细信息和按钮：
```
分组: 主流
搜索: /search?wd={{key}}
[诊断] [编辑] [测试] [导出] [删除]
```

#### 2.2 新增书源分组管理

- 在 `BookSourceModel` 中已有 `bookSourceGroup` 字段
- 增加分组筛选/排序功能
- 支持拖拽排序（自定义顺序）

#### 2.3 批量操作

- 多选模式：批量启用/禁用/删除
- 一键导出所有书源
- 一键备份到本地文件

---

### 🔴 Phase 3: 新增功能页面（高价值）

#### 3.1 缓存管理页

独立页面管理小说缓存：
- 按书源分组显示缓存大小
- 按书籍显示缓存章节数
- 一键清除指定书源/书籍的缓存
- 缓存策略设置（TTL、最大容量）

#### 3.2 书架/阅读历史

当前阅读进度存储在 cache_store 中，但没有独立的书架入口：
- 显示最近阅读的书籍列表
- 显示收藏的书籍
- 显示阅读时长统计
- 支持按最后阅读时间排序

#### 3.3 书源健康监控

基于现有的 `NovelSourceCapabilityDetector`：
- 定期检测书源可用性（可手动触发）
- 显示成功率/响应时间统计
- 失败的書源标红提醒
- 书源变更通知（URL 失效时）

## 四、执行建议

### 推荐执行顺序

| 阶段 | 内容 | 风险 | 工作量 | 收益 |
|------|------|------|--------|------|
| **P1** | 统计信息条 + 缓存管理入口 | 低 | 2h | 高 |
| **P1** | 搜索结果排序/筛选 | 低 | 2h | 中 |
| **P2** | 书源卡片改列表行 | 中 | 4h | 高 |
| **P2** | 发现页分组卡片化 | 中 | 3h | 中 |
| **P3** | 书架/阅读历史页 | 低 | 3h | 高 |
| **P3** | 缓存管理页 | 低 | 2h | 中 |
| **P4** | 书源健康监控 | 中 | 4h | 中 |

### 建议优先执行

1. **统计信息条** — 一行代码级别的改动，但用户体验提升明显
2. **书源卡片改列表行** — 解决手机上的核心痛点（按钮放不下）
3. **书架/阅读历史** — 利用已有的阅读进度数据，无需新存储

## 五、技术要点

### 5.1 统计信息条实现

- 复用 `NovelRepository` 的 `CacheStore` 读取缓存大小
- 使用 `BookshelfManager` 获取书架统计
- 所有数据在 initState 中异步加载

### 5.2 书源卡片重构

- 保持 `BookSourceManager` 不变，只改 UI 层
- 使用 `ListTile` 替代 `Container` 卡片
- 折叠/展开使用 `AnimatedCrossFade` 过渡动画

### 5.3 缓存管理

- 遍历 `CacheStore` 的所有 key，计算大小
- 按 namespace 分组展示
- 提供 `cache.clear(key)` 接口
