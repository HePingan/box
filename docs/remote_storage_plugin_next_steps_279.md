## 2. 第 1 组：低风险体检项（逐条）

### O1 冲突扫描：N 次 HEAD → 1 次 PROPFIND
- 现状：选 50 个文件上传 = 50 次串行往返；弱网/NAS 上这是分钟级等待，且每失败一次就 2 次重试。
- 改动：`scanConflicts` 先 `client.list(targetDir)` 建 `Set<String>`（用 PROPFIND 已返回的条目名），本地集合求交集；目录不存在/不可读时降级回原逐文件 HEAD。注意 `list()` 会按账户设置过滤系统目录、并比对 `displayname`——冲突判定应改用 **href 派生的 basename**（与上传时 `sanitizeRemoteSegment` 使用的名字同源），否则 displayname ≠ 文件名的服务器会误判。
- 收益：50 文件的冲突扫描从 ~50 次往返降到 1 次。
- 成本：约 40 行 + 2 个单测（假传输层断言"只发 1 次 PROPFIND"）。

### O2 重试分类 + 退避
- 现状：`catch (e)` 一律重试；密码错也要白等 2×800ms；重试从头传。
- 改动：
  1. 新增 `bool isRetryableRemoteError(Object e)`：`timeout / network / certificate(仅自签开关切换后)` 与 HTTP `429/500/502/503/504` → 可重试；`unauthorized / forbidden / notFound / methodNotAllowed / conflict / insufficientStorage / http(其余 4xx)` → **立即失败不重试**。
  2. 退避：`800ms → 2s → 5s`（`kTransferRetryDelays`），若响应带 `Retry-After` 则取 max。
  3. UI：失败态区分"重试中(第 n/2 次)"与"已失败"，避免用户误以为卡住。
- 收益：凭证/权限类错误即时反馈；弱网抖动成功率提升；不浪费配额。
- 成本：约 60 行 + 3 个单测（401 不重试、429 重试且遵守 Retry-After、退避序列）。

### O3 目录列表：加 `getetag` + 会话内 TTL 缓存
- 现状：每次进目录全量 PROPFIND；无任何缓存；无 etag。
- 改动：
  1. PROPFIND 属性集加 `<d:getetag/>`（`webdav_client.dart:365-370`），`RemoteStorageEntry` 增 `etag` 字段（可空）。
  2. `RemoteStorageService` 内加按 `accountId + path` 的 **15s TTL 内存缓存**（含 LRU 上限，例如 200 个目录），下拉刷新与写操作后强制失效。缓存命中的目录瞬时渲染。
  3. etag 存下来后即具备后续能力：上传前 `If-Match`/`If-None-Match` 条件写、以及"跳过未变化文件"的增量同步。
- 收益：返回上一级再进入不再重列；弱 NAS 上体验最直观的一项。
- 成本：约 120 行 + 4 个单测（TTL 命中、写后失效、etag 解析、无 etag 服务器的降级）。
- 注意：缓存必须按账户隔离（同一路径不同账户内容不同）。

### O4 PROPFIND 解析移出主 isolate
- 现状：上千项目录的 XML DOM 解析在 UI isolate，直接掉帧（原方案 §9 风险 2 已预见"上千项时排序有延迟"）。
- 改动：解析函数做成纯函数（已是静态私有方法），在 `compute()`/`Isolate.run()` 里跑；排序与系统目录过滤一并移入。首屏优先（先渲染前 50 项，其余异步补齐）作为可选项。
- 收益：大目录不卡帧；为将来做"深度搜索/增量同步"留出空间。
- 成本：约 50 行 + 1 个性能用例（构造 2000 条 fixture，断言解析在后台且结果一致）。

### O5 配额显示
- 现状：只有上传失败后才知道空间不足（507）。
- 改动：PROPFIND 请求 `quota-available-bytes` / `quota-used-bytes`（放 `allprop` 之外的显式属性集，多数组件返回不一致，缺省即不显示）；在账户卡片与上传前摘要里显示"剩余 X"。
- 收益：默认关闭的"信息项"，但填对了能救一次大文件上传。
- 成本：约 40 行 + 2 个单测（属性缺失不崩、格式化复用 `formatRemoteBytes`）。

### O6 文件名/路径健壮性
- 现状：`sanitizeRemoteSegment` 只看 `text.length > 255`（UTF-16 单元），CJK 名 200 字符 = 600 字节，服务端拒绝；未处理首尾空格/点（Windows 侧 SMB-DAV 会截断）；未做 NFC 归一（群晖/macOS 存 NFD，输入 NFC 会 404 或生成重复文件）。
- 改动：
  1. 长度按 **UTF-8 字节** 判 255（保留 UTF-16 兜底）。
  2. 拒绝/修剪首尾空格与结尾点；拒绝 Windows 保留名（`CON/PRN/AUX/NUL/COM1…`）。
  3. 出站路径做 `NFC` 归一，入站 href 解析出的名字做 `NFC`（显示用），字节比较时统一。Dart 侧无内置 NFC，需要 `unorm_dart` 之类依赖——**若不想新增依赖，则退化为"按原样透传 + 404 时提示可能存在 Unicode 归一差异"**（成本更低，收益递减）。
- 收益：中文/重名场景少一批"看起来能传、实际失败"的工单。
- 成本：约 50 行（不含 NFC 依赖）+ 4 个单测；NFC 部分单独立项评估依赖。

### O9 诊断：请求级日志
- 现状：只在异常时落日志（`:143-148`），成功路径无痕。
- 改动：在 `DioWebdavTransport.send` 里记 `method host path → status, 耗时ms, 字节数`（debug 级，脱敏：不含用户名/密码，路径可按需截断），失败时升级为 warn/error。
- 收益：`404 路径前缀错` / `401 应用密码错` / `507 空间不足` 这类问题一眼可判；也是 O1/O2/O3 的验收工具。
- 成本：约 30 行 + 1 个单测（断言日志频道与级别）。

## 3. 第 2 组：B 档（原方案已拍板）+ 同批增量

原方案 §11.2 已拍板：B1 写操作（MOVE/DELETE/MKCOL，二次确认）、B2 导出到公共下载（SAF/相册，64MB 内存阈值）、B3 断点续播 + 字幕（投屏不做）。**这些需要重做**（§0.2 第 2 条）。

同批建议一起做的两件小事（它们与 B1 共享同一批 UI 改造，单独做要多付一次回归成本）：

- **B1+ 多选批量**：浏览页长按进入多选 → 批量下载 / 批量删除 / 批量移动。`webdav_client` 只需 `delete/move` 单次调用，批量是 UI 层的循环 + 队列复用。
- **B1+ 账户内 COPY**：`COPY` 与 `MOVE` 同一套代码路径，多一个方法而已；跨账户传输只能靠"下载再上传"（服务端不支持），不建议做。

B 档的实现要点（补原方案未写细的部分）：
- `MOVE`/`COPY` 必须带 `Destination` 头（**绝对 URL、已百分号编码**），并处理 `201/204/207`；
- 目标存在时 `Overwrite: F` 语义要显式设置，避免"静默覆盖"（与 B1 的二次确认文案对应）；
- `MKCOL` 成功码是 `201`，`405` 表示已存在——文案要与 `conflict` 映射区分；
- 删除目录递归与否由服务器决定（多数实现递归），确认文案要写清"目录内所有内容一并删除，不可恢复"。

> 附：本次核对用到的复现方式（供复核）—— 线上 APK 的 `lib/app-release.apk` 与 278 构建产物解出 `lib/arm64-v8a/libapp.so`，对其做 **UTF-16LE / ASCII 精确子串计数**（CJK 字面量在 AOT 快照里是 UTF-16LE，直接按 UTF-8 grep 会全为 0，别被误导）；不要用"二进制差异行数"判断功能差异，AOT 快照在同一源码上也不稳定（本次两包差异字节占 91%，与功能无关）。
