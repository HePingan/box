## 二、依赖决策

`dart:ui` 的 `ImageByteFormat` **只有 png**，没有 JPEG 编码 —— 这意味着
"把图压小""转成 jpg"这两类事用 Canvas 根本做不到（PNG 无损，原尺寸重编码只会更大）。
所以必须引入图像库。

选了 `image 4.12`（纯 Dart，无原生依赖）。这个选择牵出一个依赖冲突：
- `image ≥4.6` 要求 `archive ^4.x`
- `image <4.9` 要求 `xml ^6.x`，而本项目是 `xml ^7`

两头都堵。最终选**升 archive 到 4.5**（它在本项目只用于漫画导入器的 ZipDecoder，
影响面最小）。

### 升级暴露的两处真实行为差异

1. `entry.content` 已是 `Uint8List`（3.x 是 `dynamic`），强转变成多余；`encode()` 不再可空。
2. **archive 4.x 对垃圾字节不再抛异常，而是返回空归档。** 这点很重要：损坏的 cbz
   原本提示「导入失败」，升级后会变成「文件中没有找到图片」—— 用户只会反复换文件重试。
   已在导入器里按 **zip 魔数**补一道校验，同时刻意保留「合法空 zip 返回空列表」的
   既有语义（两者对用户是不同的提示）。

## 三、四个 domain 模块的"防挨骂"规则

这些规则是本轮的重点 —— 每个都对应一个用户会立刻察觉的糟糕体验：

### 压缩
- **只缩不放**：放大只会糊且更大
- **尺寸没超限就不重编码**：重编码必掉画质
- **压完比原图大时 `isWorthSaving` 为假**：界面据此保留原图，
  绝不对着一个更大的文件说"已压缩"
- 带透明的图压成 JPEG 时铺白底（直接编码会丢掉 alpha 而保留原 RGB，透明区变黑/乱色）

### 格式转换
- JPEG/BMP 没有 alpha。强制让用户选底色，并在结果里如实标记 `hadAlpha`，
  不做"悄悄丢掉透明通道"

### 水印
- **只支持 ASCII，中文一个像素都画不出来**。这不是"画得难看"，是位图字体的
  字形表里没有汉字。实测 `drawString("中文")` 的深色像素数为 **0**，而
  `"Hello"` 是 299。
- 所以 `textRenders()` 让 UI 在用户按按钮**之前**就提示，而不是让他对着
  一张没有水印的图发愣。
- 想支持中文要走 `dart:ui` 的 TextPainter 渲染或打包汉字 TTF，属独立一版。

### 拼接
- **等比缩放 + 居中留边，绝不拉伸**。硬塞进等大格子就是拼接类工具最常见的
  差评来源（人脸变胖）。测试用宽高比断言锁住。
