## 二、组 1：趣味游戏（建议本轮，5 个）

### 为什么是它

`趣味游戏` 分类**可见 1 条、未接线 7 条** —— 是唯一"看起来像功能但只有一个入口"的分类。用户点进游戏分类只看到一个条目，观感上就是"这块没做完"。

7 条是：扫雷 / 2048 / 数字华容道 / 五子棋 / 贪吃蛇 / 迷宫 / 数独。

**全部是纯本地算法，零网络、零新依赖**，和上一轮的九宫格切图同类。
`local_tools/domain/` 已有清晰的分层模式（纯逻辑 + 单测，UI 只收输入画结果）。

### 建议做 5 个，不做 2 个

| 做 | 理由 | 预计 |
|---|---|---|
| **2048** | 规则最清晰，纯状态机，最适合单测（合并/移动/结束判定） | 0.5 天 |
| **扫雷** | 首次点击必须安全，是唯一有"生成算法"要求的；好测 | 0.5 天 |
| **数独** | 生成器 + 唯一解校验，算法含量最高，用户价值也高 | 1 天 |
| **迷宫** | DFS/Prim 生成 + BFS 求解，可复用数独的"生成器"测试模式 | 0.5 天 |
| **贪吃蛇** | 唯一需要帧循环的，考验 setState 与 dispose | 0.5 天 |

| 不做 | 理由 |
|---|---|
| 五子棋 | 需要 AI 对手才好玩，落子判定简单但"跟谁下"是产品问题 |
| 数字华容道 | 与 2048 同属滑块类，做了 2048 就有重复感 |

**分批**：先做 2048 + 扫雷（1 天可发版验证），做完再决定是否继续。
不建议一次 5 个 —— 游戏类最怕"数量够了但每个都不好玩"。

### 验收
- 每个游戏的 domain 层单测覆盖：初始状态、每一步合法性、胜负/结束判定、边界（棋盘满、无可动）
- 2048 要有"滑动方向真的合并了"的用例（不是只测不崩）
- 扫雷要有"首次点击不会踩雷"的用例（这是扫雷唯一的硬规则）
- 数独要有"生成的题有且仅有一个解"的用例（生成器最容易出的错）

预计 0.5 天，产出 `docs/silent_failure_audit_2026XX.md`。

## 四、组 3：水印中文支持（可选，0.5 天）

上一轮的水印只支持 ASCII —— `image` 包只内置 arial14/24/48 三款位图字体，
实测 `drawString("中文")` 的深色像素数为 **0**（不是难看，是一个都不画）。

现在 UI 会在输入框下方提示，但用户真正想要的是**能写中文**。

方案：改用 `dart:ui` 的 `TextPainter` 把文字渲染成一张透明 PNG，再
`compositeImage` 叠到原图上。`dart:ui` 自带系统中文字体，不需要打包 TTF。

代价：要处理字体加载（`TextPainter` 在非 widget 环境需要 `ui.ParagraphBuilder`）
与 DPI（按目标图片尺寸算 fontSize，不是按屏幕密度）。

**风险**：`TextPainter` 依赖 Flutter 引擎，在纯 Dart 单测里跑不了 ——
需要拆成「文字→图片」与「图片→合成」两段，后者可测。
