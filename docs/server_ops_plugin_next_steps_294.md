### 1.1 与既有文档不符之处（先说这个）

1. **291 说 A11 是"30 秒"，今天复测是 54 秒** —— 同一台机器、同一目录口径（758 条目），代价翻倍。
   不改变结论（这一项要做），但**改变优先级**：它是目前唯一还能让 App 表现为"卡死"的地方。
2. **291 的 A12 只写了"上传若探测不支持续传，就只做重试"**，没写这条硬约束：**绝不能发
   `Content-Range`** —— rclone 会忽略它并把文件覆盖成"这一段"，是**静默的数据损坏**（实测见 1.3）。
   凡是"分段上传"的想法都到此为止。
3. **"悬挂 API 0 个"不等于"每个方法都有界面入口"**（事实基线第 7、8 条）：`logs` 全程合格地
   挂在闸门外。这是本方案新增 F1 的原因。

### 1.2 大目录的代价（复现）

```bash
PW=$(cat /root/.secrets/box-ops-webdav.password)
for d in usr/lib64 etc root; do
  curl -s -o /tmp/pf.xml -u "boxops:$PW" -X PROPFIND -H 'Depth: 1' \
    "https://box.hpa888.top/dav/$d/" -w "$d %{size_download} B %{time_total}s\n"
done
# usr/lib64 484517 B 53.97s（758 条） / etc 129544 B 1.83s（231 条） / root 148565 B 2.70s（248 条）
```

根因不变：`--dir-cache-time 0` 是刚需（否则新上传的文件看不见），所以**服务端这条路降不下来**，
只能在客户端把体验做对。

### 1.3 续传的边界（今天探明，决定 A12 的形状）

```bash
# 上传侧：先 10 字节，再用 Content-Range 发后 5 字节
curl -u "boxops:$PW" -T <10B>  .../tmp/ops-resume-probe.bin        # 201，大小 10 B
curl -u "boxops:$PW" -H 'Content-Range: bytes 5-9/10' -T <5B> ...  # 201，大小变成 5 B ✗
# 下载侧：
curl -H 'Range: bytes=5-'  → 206，5 B，内容 56789
curl -H 'Range: bytes=0-4' → 206，5 B，内容 01234
curl -H 'Range: bytes=-3'  → 206，3 B，内容 789
```

结论：**下载可以续传，上传不能**；上传侧还要主动禁止这个头（否则客户端一"优化"就损坏文件）。

### 1.4 通道凭据使用情况（原型）

```bash
ssh hpa888 'awk "{u=\$3; if (u!=\"-\") {c[u]++; last[u]=\$4\" \"\$5}} END {for (k in c) printf \"%-28s %5d 次 %s\n\", k, c[k], last[k]}" /www/wwwlogs/box-ops-access.log | sort -k2 -rn'
# ro-probe-hpa888 40 次 / ro-probe-175 40 次 / boxops 39 次 / gate-rw-<已撤销> 31 次 …
```

这条汇总现在**只有我会跑**：用户无法在 App 里看到"我的设备用的还是旧口令"。而"旧口令能不能退休"
正是 C1 的最后一步 —— 所以要把它做成**看得见**的（本方案 D3）。

## 二、路线分组（顺序即执行顺序）

### D 组：低风险、能立刻感知（建议本轮）

**D1（承接 A11）. 大目录：条目上限 + 继续加载 + 可取消**

- 现状：`PROPFIND Depth:1` 一次拿全量；`/usr/lib64` 758 条目要 **53.97 秒 / 484 KB**，这 53 秒里
  页面没有进度、没有取消、也没有"这目录很大"的提示。代码：`files_tab.dart:85 _load()`、
  `:96 _entries = entries`（一次 setState 灌全量）、`:1495 ListView.builder`、`:805` 只有一句
  `CircularProgressIndicator`。
- 机制：代价在服务端（`--dir-cache-time 0` 每次都要重新 stat 每一项），客户端唯一能做的是
  "别一次渲染完、别无声等待、允许退出"。
- 改动：① 默认渲染前 300 项，底部给「还有 M 项，继续加载」（M 来自真实条数）；② 请求中显示
  "正在列举（大目录可能较慢）"+ 取消按钮（取消后不再 setState）；③ 区分"服务端 5xx""超时"
  "401/403"三类文案；④ 列目录的 5 秒阈值：超过就提示"该目录较大"。
- 收益：`/usr/lib64`、`/usr/lib/python3`、`node_modules` 这类目录不再表现为"App 卡死"。
- 成本：0.5–1 天。验收：假服务返回 2000 项 → 只渲染 300、点继续 600、取消后无 setState；
  live 用例打真 `/usr/lib64` 断言"首屏可见且未阻塞"。

**D2（新）. 把 `logs` 接上界面：服务端日志尾部（「系统」页新增「日志」小节）**

- 现状：服务端 `act_logs`（`box_ops_api.py:466`）已能读白名单内的日志尾部（实测
  `/www/wwwlogs/access.log` 2 行 ✅），客户端方法在（`server_ops_api_client.dart:229`），
  但 **`lib/` 内零引用** —— 用户在 App 里看不到日志文件（服务抽屉里的那 30 行是 journal，
  另一个接口）。运维最常用的动作之一在 App 里是**缺的**。
- 改动：① 服务端加一个只读动作 `logfiles`（列 `LOG_ROOTS` 下的候选日志文件：名字+大小+时间，
  不返回内容）；②「系统」页新增「日志」小节：选文件 → 尾部 N 行（复用 `logs`，默认 100、上限
  `MAX_LINES=500`）；③ 顺手把 `/tmp` 从 `LOG_ROOTS` 默认值里去掉（`box_ops_api.py:65`，那是自检
  用的路径，生产不该当日志根；自检自己会覆盖它）。
- 收益：`nginx 报错 / 更新服务日志 / 我方的 box-ops 审计` 这些手机上就能看，不必开终端。
- 成本：0.5 天。验收：假服务 + live 各一条；白名单外路径必须 403（已有行为，回归守住）；
  `logfiles` 不返回文件内容（只有元数据）。
- 边界：这是**只读**动作，与写档无关；不发 Content-Range、不下载整文件。

**D3（新）. 通道凭据可见化：「这台设备用的是旧口令还是设备凭据」**

- 现状：C1 落地的是一台设备一条凭据，但**没有任何界面/接口**能回答"旧口令还在被谁用"（1.4 的
  汇总只有手动 ssh 才看得到）。于是下一步"删掉 `boxops` 那一行让旧口令退休"只能靠猜。
- 机制：那四个入口的 nginx access log 里本来就有 `$remote_user`（第十六节专门为此加的）。
- 改动：① 服务端加只读动作 `channel`：解析 `/www/wwwlogs/box-ops-access.log` 的**最近 N 行**
  （默认 5000，可传 `days`），按 `$remote_user` 汇总 —— 次数、最近时间、用过的入口数、状态码分布，
  并标注该用户名**现在是否还在 htpasswd 里**（`legacy` / 在用 / 已撤销）；② App 在**体检面板**加一行
  "通道凭据（最近 7 天）"，旧口令那一行用醒目文案："还在用旧通道口令（39 次）——换完设备凭据后
  就可以在服务端删掉它"。
- 收益：把 C1 的收尾从"说不清"变成"看得见"；也顺手把"已撤销的凭据是否真的不再出现"变成可核对的数据。
- 成本：0.5–1 天。验收：假服务注入一段真实格式的日志 → 汇总数字与用户名正确、不含 URI；
  live 用例断言汇总里出现巡检凭据 `ro-probe-*` 与 `boxops`。
- 边界：只返回**用户名/入口/计数/状态码**，**绝不返回 URI**（URI 里有目录名），只读、有审计。

### E 组：要动传输主路径（单独立项）

**E1（承接 A12）. 大文件：下载续传 + 上传"明确重试"**

- 现状：无 `Range`/`resume`（事实基线第 3 条）；传输中断一律从头。
- 机制（今天探明，见 1.3）：**下载侧** rclone 的 Range 完全正确（三式全 206）；**上传侧不支持
  续传**，而且带 `Content-Range` 的 PUT 会把文件覆盖成"这一段" —— 是静默损坏，必须禁止。
- 改动：① 下载：写 `.part` 分片，同名断点用 `Range: bytes=<已收>-` 续，收完校验大小（可选
  sha256）再改名；② 上传：**不发送 `Content-Range`**，失败重试前先 `DELETE` 目标（避免
  "201 覆盖"语义下留半个文件），文案写明"会从头重传"；③ 传输页显示"已传 x MB / y MB"。
- 收益：几十 MB 的日志/备份包不再因为一次掉线全丢；同时把"静默损坏"这条风险从代码层面关掉。
- 成本：1 天。验收：live 用例 —— 下载 10 MB 文件在 5 MB 处断开后续传，拼接后 sha256 与直连一致；
  上传用例断言请求里**没有** `Content-Range`。

### F 组：工程守卫（顺手做）

**F1（新）. 闸门口径升级：把"只有测试在调"的公开方法单独报出来**

- 现状：`tool/scan_dangling_apis.py:48` 的 `SEARCH = ["lib", "test"]`，于是"接口存在、测试齐全、
  界面零引用"的半成品不会被报（`logs` 就是人肉才发现的，事实基线第 7、8 条）。
- 改动：在现有"零调用即红"之外加**警告档**（不影响退出码）：一个公开方法若在 **`lib/` 内零引用**
  （按**裸名字**统计，把 `client.overview` 这种方法引用也算上，避免误报），就列出来，逐条判
  "接线或删掉"。同时把这条口径写进脚本 docstring 的"已知边界"。
- 收益：下次再出现"有接口没界面"的功能，闸门当场说话，不用靠读代码撞见。
- 成本：0.25 天。验收：跑一次能列出 `logs`（本轮接线后应消失）与 `debugAwaitPersistence`
  （判断是接线还是删掉），且 CI 退出码不变。

### 6.1 实施过程中新发现的事实（都改了）

1. **`logs` 的白名单能被符号链接绕过（真漏洞，已修）**：白名单前缀是在 `resolve()` **之前**
   查的，所以白名单目录里放一条 `x -> /etc/shadow` 就能读它。现在 resolve 之后再查一次
   前缀，符号链接一律不算白名单；自检里加了这条拒绝用例（`logs` 与 `logfiles` 各一条）。
2. **闸门还有反方向的毛病：把方法当回调传（tear-off）不算调用点**。做 D3 时
   `pull('通道凭据', client.channel)` 让闸门报了 **1 个悬挂**——而它明明接了线。
   现在引用口径是 `名字(` **与** `.名字` 两种，tear-off 也算引用。
3. **黄灯档落地后立刻报出一个真的**：`clearMemory`（远端存储插件的缩略图缓存释放）
   `lib/` 内零引用、只有 `test/` 在调 —— 和 283 那次的 `clearThumbnailCache()` 同形。
   它在 `remote_storage`，不属本轮范围，**留在黄灯里可见**（要么接内存压力/离开页面时调，要么删）。
   另一个 `debugAwaitPersistence` 是写明的测试钩子，已进 `ALLOW` 白名单。
4. **日志白名单去掉了 `/tmp`**：生产上不该把 `/tmp` 当日志根；自检本来就覆盖临时目录，
   所以行为不变（`LOG_ROOTS` 现在只有 `/var/log`、`/www/wwwlogs`、更新服务日志三处）。
5. **自检的临时目录不再跟随 `TMPDIR`**：`TMPDIR` 可能指向 `/root/.hermes`（被 du 黑名单
   拒绝的密钥类路径），会让 `diskusage` 那项"因为环境"假失败。
6. **通道访问日志只在边缘机**：`channel` 在看不到日志的机器上回 `available:false` + 指路
   （"换到 hpa888 那条看"），而不是假装"没有凭据在用"。App 侧按同口径渲染。

### 6.4 界面不再把人往错的地方带（297，用户说"顺便优化一下 UI"）

|---|---|

## 6.5 D7：切了机器"没有显示"（2026-09-26）

用户真机反馈："切换服务器一个显示当前，一个切换了没有显示"，截图里顶部切换器写着
**「新服务器」**、服务器页两张卡片**都没有「当前」**标记。

服务端没问题（快照里两台都在），三个问题都在客户端：

| 现象 | 根因 |
| --- | --- |
| 顶部显示「新服务器」 | 新建服务器的默认名就是它，用户没改名 → 切到这台后顶部一直显示它 |
| 两台卡片都没有「当前」 | 「当前」是按 `host.id == currentServer.effectiveSnapshotId` 打的；自建条目的 `snapshotId` 默认等于自己的 id（`srv1`），而快照里的 id 是 `hpa888` / `tencent175` → 对不上 → 永远打不上 |
| "切换了没有显示" | 上面两条的合成：列表里"设为当前"那个圆点**永远画的是空心**（`radio_button_unchecked` 写死），切了也没有任何反馈 |

改法（都在客户端，服务端未动）：

1. **规整数据**（`ServerOpsSettings.normalizeForSave` / `normalized`）：
   * 名字还是占位名（`新服务器`）→ 按地址取名（地址与内置某台相同就用那台的名字，否则用"主机+路径"）；
   * 自建条目的**快照 id 按地址对齐** → 撞内置 175 的条目会挂到 `tencent175`，卡片上就能打上「当前」；
   * 选中的那台"连地址都没有"→ 换成第一台有地址的（别把整页指向空）。
   **读的时候也规整一遍**（`load()` 里 `.normalized()`）—— 已经存进本机的旧数据不能等用户手动保存才恢复。
2. **"设为当前"的圆点反映状态**：当前那台是实心 + 禁用 + tooltip「已是当前机器」。
3. **撞了内置的条目直说**：副标题提示「⚠ 和「腾讯云 · 构建/监控机」是同一台机器 —— 用那条更省事，这条可以删掉」（只对"自建撞内置"这个方向提示，不去烦内置那两条）。
4. **服务器页多一行兜底说明**：当前这台在快照里找不到对应 host 时，直接写出来（"当前这台（X）不在监控快照里 —— 快照里是：hpa888、tencent175"），不再让它静默地什么都没有。
5. 名称输入框提示改成「留空就按地址自动取名」（以前是一句示例名，等于鼓励留空之后顶着"新服务器"跑）。

地址比对（`addressKey`）按"协议无关 + 结尾斜杠无关"归一：真机上填的是 `//box.hpa888.top/dav175` 这种省协议的写法。
