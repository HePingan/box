# 伪装图标清晰度：从 128px 位图到 48dp 矢量（2026-11-15）

## 现象

1.21.29+386 已经把伪装图标换成真机 `drawable/app_icon` 的**字节级拷贝**（变体选对了：
深底 + 浅符号 + 橙色等号那张，不是 `drawable/icon` 的浅底版），但用户真机上还是觉得
「图标很糊」。

## 成因（实测，不是猜）

源 APK（vivo 系统计算器 `com.android.bbkcalculator` 15.6.1.1）里 `drawable/app_icon`
只有四档，而且是按 **32dp** 出的图：

| 密度 | 像素 |
|---|---|
| hdpi | 32×32 |
| xhdpi | 64×64 |
| xxhdpi | 96×96 |
| xxxhdpi | 128×128 |

Android 桌面图标槽位是 **48dp**：xxxhdpi 要 192px、xxhdpi 要 144px。我们给 128/96，
桌面只能自己插值放大（xxhdpi 设备放大 1.5 倍，xxxhdpi 设备 1.5 倍以上）→ 边缘和 5px 的
笔画全糊。字节拷贝在「画得像」这一层是对的，但它把分辨率上限也一起拷过来了。

## 做法

`tool/gen_disguise_icon.py` 改成：从源图那张 128px **拟合出参数化矢量**，再按 48dp
各密度重新栅格化。

- 颜色/圆心/半径/笔画长宽全部从源图量出来，然后 8 倍超采样重绘、降采样到 128 与源图
  逐像素比对，坐标下降微调参数（`GEOMETRY` 里的数值就是这么来的）；
- **保真度可验证**：脚本会把自己渲的 96px / 128px 与源 APK 里那两张逐像素比，
  平均误差 > 4/255 或「三通道差 ≤24 的像素占比」< 90% 直接报失败；
- 形状语言跟源图走：笔画是**圆头**（源图加号/等号末端是圆角），外框是圆角矩形
  （圆角 31.6/128，按行扫 alpha 轮廓与源图逐行一致，±1px 抗锯齿）。

产出五档（48dp 语义）：mdpi 48 / hdpi 72 / xhdpi 96 / xxhdpi 144 / xxxhdpi 192。
源 APK 没有 mdpi，我们补上，省得 mdpi 设备去放大 hdpi。

**不给 anydpi-v26 自适应图标**（这条没变）：被仿的应用没有，桌面走位图路径；给了日后
桌面会把 108dp 裁到 72dp 再套蒙版 = 放大 1.5 倍并切边，就是「变形」的来源。

## 实测结果

| 指标 | 值 |
|---|---|
| 保真（96px） | 平均误差 2.35/255，误差≤24 占比 95.0% |
| 保真（128px） | 平均误差 2.21/255，误差≤24 占比 95.1% |
| 轮廓 | alpha 逐行 xmin/xmax 与源图一致（y≥2 全等，仅最上一行差 1~2px 抗锯齿） |
| 锐度（梯度均值，192px 显示） | 旧 1.91 → 新 2.75（128px 源图自身 2.77） |

也就是说：新图在同尺寸显示下，边缘锐利度已经回到「源图原生分辨率」的水平，而旧做法
因为被桌面放大掉了约 31%。

## 复现

```bash
/root/anaconda3/bin/python tool/gen_disguise_icon.py --apk /root/calc-probe.apk          # 校验 + 重渲染写盘
/root/anaconda3/bin/python tool/gen_disguise_icon.py --apk /root/calc-probe.apk --check  # 只校验
```

脚本跑完会打印五档 sha256，改图后同步
`test/disguise/disguise_android_contract_test.dart` 里钉的哈希与边长（契约测试现在还多钉了
一条「xxxhdpi ≥192px」，防止有人为了省事退回拷 128px 的字节）。

## 还没解决的（老实说）

桌面槽位若比 48dp 更大（部分 ROM 是 56~64dp），192px 仍会被轻微放大。真要再进一步只能
把 xxxhdpi 塞 256px，但那会把 intrinsic 尺寸从 48dp 变成 64dp，个别不强制 bounds 的桌面
会画得比真计算器大一圈 —— 属于「为了锐度冒尺寸风险」，先不做，等真机反馈再定。
