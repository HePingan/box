# 设计方案：AI 读屏命中题 → 自动上报题库后端「待审核」区

> 状态：**待拍板**（本文档只做设计，不含代码改动）
> 日期：2026-09-13
> 需求原话：「像这种使用大模型搜索过的题能不能帮我直接传至题库管理后端的待审核区域，新题查询过一遍后续等我从后端审核通过后再次拉取到本地就很快，不用使用ai就可以秒出答案」

---

## 一、结论先行：**这个闭环后端和客户端「都已经有了」，只差一根线**

我回读了真实代码，两端的零件全都现成，**不需要新造任何接口**：

| 环节 | 现有实现（已核实） | 位置 |
|---|---|---|
| ① 客户端投稿 | `QuizCloudSyncService.submit()` → `POST /api/quiz/submissions`（Bearer token） | `quiz_cloud_sync.dart:394-418` |
| ② 后端收稿入待审核 | `submitQuizQuestion()`：校验 → 建 `QuizSubmission(status:'pending')` | 后端 `:1580-1638` |
| ③ 后端人工审核 | `GET /admin/quiz/submissions/pending`、`POST /admin/quiz/submissions/<id>/approve\|reject` | 后端 `:617-660` |
| ④ 审核通过发布 | `reviewQuizSubmission` action=approve → 写 `quizQuestions[published]` + `recordQuizChange(id,'upsert')` | 后端 `:2596-2618` |
| ⑤ 客户端增量拉回 | `GET /api/quiz/sync` 按游标增量拉取已发布题 | `quiz_cloud_sync.dart:281` |
| ⑥ 本地秒出 | 命中本地库即返回，不触发 AI | 既有搜题链路 |

**因此本需求 = 「把 ①的入参，从『用户在题库页手动勾选本地题』换成『AI 读屏的一次命中结果』」。**

## 二、真实数据契约（逐字核对，非推测）

### 2.1 客户端投稿必填字段
`POST /api/quiz/submissions`（后端 `validationError` 原文 `:5858-5864`）：

```
题干不能为空
单选题至少需要两个选项
正确答案不能为空
正确答案过长（>200）
```

### 2.2 AI 读屏结果**是否够用**？

读屏提示词（`quiz_engine.dart:1119-1126`）已要求模型返回：

```json
{"stem":"题干原文","options":["A. xxx","B. xxx"],"answer":"A","confidence":0.95}
```

落到 `QuizResult` → `QuizAnswer`，携带 `options` / `correctAnswer` / `confidence`（已核实 `quiz_engine.dart:105-125`）。

**逐字段对照：**

| 投稿必填 | 读屏是否提供 | 结论 |
|---|---|---|
| 题干 | ✅ `stem` | 够 |
| 选项（单选≥2） | ⚠️ `options` **模型可能返回空数组**（截图选项被裁掉/识别失败时） | **有坑，见 §3.2** |
| 正确答案 | ✅ `answer` | 够 |
| 分类 `category` | ❌ 无 | 可留空（后端非必填） |
| 题图 `image` | ⚠️ 有截图 bytes，但 `_tryVisionFallback` 当前**用完即弃** | **需改：留一份**，见 §3.3 |

### 2.3 后端撞重逻辑（重要，影响"要不要提交"）
`submitQuizQuestion`（`:1607-1621`）会自动：

- **同题干+同图已发布** → `status='merged'`（"正式题库已存在相同题目与图片"），**不会重复入库**
- **同题干+不同图** → `reviewNote='同文不同图，进入补图审核'`（走补图审核）
- 否则 → `pending` 正常待审核

→ 说明**重复提交是安全的**，后端会自己合并，不会污染题库。**这一点很关键**：客户端可以放心"无脑提交"。

### 2.4 认证前提（硬约束）
`POST /api/quiz/submissions` 走 `requireUser(request)`（`:329`）——**必须登录**。另有插件策略闸门 `builtin_quiz_bank_view` / `feature: 'cloud_push'`（`:1581-1591`），被禁用会 403。

→ **未登录或未开云推送权限时，本功能不可用。**

## 三、设计

### 3.1 数据流（新增部分用 ★ 标出）

```
AI 读屏命中（本地未命中 → 截图 → 模型返回 stem/options/answer）
   ↓
★ 构造候选 QuizBankItem（question/type/options/correctAnswer/image）
   ↓
★ 本地落一条"待投稿"记录（syncStatus = draft/pendingReview），不阻塞悬浮窗
   ↓
★ 时机一：立刻静默提交（若已登录 + 云推送已开）
  或 时机二：攒着，用户在题库页一键"投稿 N 条 AI 命中题"
   ↓
POST /api/quiz/submissions → 后端 pending
   ↓
用户在后端 /admin/quiz/submissions/pending 审核
   ↓
approve → 发布进正式题库 + recordQuizChange
   ↓
客户端 /api/quiz/sync 增量拉回 → 本地命中 → 秒出，不再走 AI
```

### 3.2 三个必须拍板的设计点

**问 1：选项缺失的题怎么办？**

模型可能只给题干+答案、不给选项（尤其图片题）。而投稿硬门槛是「单选≥2 选项」。

- **A 档（保守）**：选项不足 **不提交**，只在本地标 `draft` 并提示「该题缺选项，无法投稿」。代价：图片题基本提交不了（而图片题恰恰是 AI 读屏最有价值的场景）。
- **B 档（推荐）**：选项不足时，**仍提交**，但把截图作为 `image` 一并带上、`options` 留空 → 命中后端「同文不同图→补图审核」通道，由你人工补。代价：后端需容忍空选项的 pending（**需你确认后端是否放行**；`validationError` 目前会 400 拦下）。
- **C 档**：选项不足时，让模型**再问一次**（追加 prompt 强制列选项）。代价：+3~15s 延迟，仍可能失败。

> ⚠️ B 档需要动后端校验逻辑（放行"空选项 + 有图"的待审核稿）。**这是唯一需要改后端的地方**，其余全部客户端可完成。

**问 2：什么时机提交？**

- **A 档（推荐）**：**命中即静默提交**（后台异步，不阻塞悬浮窗显示）。最省事，符合你原话「查询过一遍后续…」。
- **B 档**：**攒批 + 手动一键投稿**。你可先在题库页看一遍再决定投哪些，质量更高，但要你多操作一步。
- **C 档**：命中即提交 **+ 悬浮窗给个"已入待审核"小徽章**（可撤销）。透明度最好。

**问 3：读屏命中该不该"无脑提交"？**

丙方案的核心假设（模型独立作答 vs 照抄界面选项）**至今未验证**（缺反例）。若模型实际在照抄界面已选项，那自动提交等于**把界面的错答案批量灌进你待审核队列**——虽然你人工审核能拦住，但会显著增加你的审核负担。

- **A 档**：无脑提交全部读屏命中（审核端兜底）。审核队列会变大。
- **B 档（推荐）**：只提交 `confidence >= 阈值`（如 0.9）的命中；低置信度的不提交或标 `draft` 待你处置。参数可调。
- **C 档**：全部提交，但后端/客户端按 confidence 排序，你先审高置信的。

### 3.3 需要改的代码点（预估工作量）

| 文件 | 改动 | 风险 |
|---|---|---|
| `quiz_plugin_entry.dart` `_tryVisionFallback` | 截图 bytes 保留一份；命中后调 `_enqueueVisionCandidate()` | **低** |
| 新增 `quiz_vision_candidate_queue.dart` | 本地队列（落 SharedPreferences 或 sqlite），字段同 `QuizBankItem` + `confidence` + `status` | **低** |
| `quiz_plugin_entry.dart` 或新 service | 复用 `QuizCloudSyncService.submit()` 提交 | **低**（接口已存在） |
| `quiz_bank_view_page.dart` | 队列可见 + 手动投稿入口 + 审核状态（**若选 B/C 档时机**） | **中** |
| 后端 `validationError` | **仅当**选 §3.2 问 1 的 B 档才需要（放行空选项+有图） | **中**（改线上后端，须你拍板） |

### 3.4 我建议的最小可行方案（P0）

**A 档组合，全部客户端完成，不动后端：**

1. 读屏命中 → 保留截图 + 结果，组成候选
2. 本地落队列（`draft`），**不阻塞**悬浮窗
3. 若已登录 + 云推送开 → **静默提交**（`confidence >= 0.9` 才提交）
4. 选项不足的 → 留本地 `draft`，不提交（避开后端 400）
5. 题库页加一个「AI 命中候选（N）」入口，可看、可手动重投、可删

**这样：不动后端、不改线上数据、可自主发版。** 等真机跑一段时间看到真实数据后，再决定要不要上 B 档（空选项放行 + 补图审核通道）。

4. **§3.2 问 4（登录）**：**可以** —— 未登录时静默禁用，不打扰用户。

### 定稿：P0 实现口径
- 读屏命中 → **保留截图 bytes + 识别结果**（question/options/answer/confidence）
- 本地落队列，**不阻塞**悬浮窗渲染
- **选项 >= 2 且 confidence >= 0.9 且已登录且云推送已开** → 静默提交
- **选项不足 → 只落本地 draft，保留截图与识别信息，等待手动补充**（不提交）
- 题库页新增「AI 命中候选(N)」入口：可查看、可手动补充选项后再投、可删
- **不动后端，不改线上数据，可自主发版（非强更）**
