# 漫画源 Step 1：源自检（1.20.60 / 317）

**一句话**：把「包子漫画」这份 Legado 漫画书源当配置装进 App，用手机上的真 WebView 把
**搜索 → 打开一本书 → 打开第一章取图** 跑一遍，逐项给出「通过 / 失败 + 原因」。

这一步不是"能看漫画"，它的价值是**把未知变已知**：章节页在我们两台服务器上都是 502，
只有手机上能问出真相。

---

## 一、为什么架构只能是"App 内 WebView 取页"

实测证据（2026-09-27，两台机房机器 175 / hpa888 都试过）：

| 环节 | 实测结果 | 说明 |
|---|---|---|
| 搜索页 | **HTTP 403 + `__gatekeeper_challenge`** | 纯请求过不去；两台机房 IP 一律 403 |
| 搜索页（真浏览器） | ✅ 挑战能过，`.comics-card` 命中 **77 条** | 真实 DOM 与书源类名完全对得上 |
| 详情页 + 章节列表 | ✅ | 标题「航海王」，章节 **1211** 条 |
| 分类接口 | ✅ `/api/bzmhq/amp_comic_list` 200 JSON | |
| 封面图 | ✅ **无防盗链**（不带 referer 也 200，33KB jpeg） | `Image.network` 能直接取 |
| **章节阅读页** | ❌ **一律 502** | 更换镜像域名、从详情页点击进入（带 Referer + cookie）都一样 |

⇒ **服务端代取不可行**（JS 挑战 + 机房 IP 502，两处都是死穴）。
⇒ 唯一可行路径：**App 内的 WebView**。它既能过挑战，又能跑书源里的 `<js>` 段 ——
Dart 没有 JS 求值能力，WebView 有（Legado 自己也是这么干的）。

### 界面上的三条硬规矩

1. **每步失败必须写原因**：超时 / HTTP 状态 / 选择器 0 命中 / 规则不认识，四类分开说；
   还会把**页面标题**带出来 —— 502 这种错误只看"命中 0"是看不出来的。
2. **配置错误 ≠ 站点没数据**：规则解析不了会说「规则不认识：「…」—— 这是配置问题，不是站点问题」，
   不会被混进"打不开页面"里带偏排查方向。
3. **跑到一半就失败**：后两步标「跳过」，不是「通过」；拿到图就当场显示一张（能显示 = 图片链通）。

## 四、规则引擎：支持到哪、哪里不一样（不藏着）

支持（这份源真实用到的形状）：
- 选择器：`class.a b c`（**同一元素**上的多个类名）· `tag.amp-img` · `id.x` · 裸标签名 `amp-img`；
- 索引：`class.x.0`、`tag.amp-img.0`、单独一段 `.0`；
- 分段：`@` 分隔，逐段往里找（后代）；
- 取值：`text` / `html` / 属性名（`src` / `href` / `data-src` …）；
- **JS 段**：`<js>…</js>` 与 `@js:…` 在页面里真跑，配套 `java.*` 垫片（`getElements` / `t2s` / `baseUrl`）。

**明确没做**：
- `java.t2s` **繁转简未实现**（没词表），拿到的繁体就是繁体 —— 界面上写了这句，不冒充已转换；
- 这份源的 `ruleBookInfo.tocUrl` 第 3 段是**它自己的笔误**（`@harf@`，应为 `@href@`）：
  本 App 不照抄，章节链接改从详情页取（实测 1211 条正常）；
- Legado 的其它语法（正则、模板变量、`ajax`、登录态等）不在范围内。

## 七、取页健壮化：镜像回退 + 重试（1.20.62 / 319）

### 手机端第二次自检暴露的问题

```
· [通过] 搜索（272ms）命中 77 条，取到书名 77 个、链接 154 个
· [失败] 详情（1278ms）页面加载出错（-6 net::ERR_CONNECTION_RESET）
```

搜索页能开、**同一个域名**的详情页却被重置 ⇒ 不像域名被墙，更像"这一跳被打断"。
所以做的不是"绕过"，而是**重试 + 换镜像**，并且把波折如实报出来。

### 镜像的真实可用性（真浏览器逐个试，2026-09-27）

| 镜像 | 详情页 | 章节页 |
|---|---|---|
| `cn.baozimhcn.com`（源里的主站） | ✅ 1211 章 | ❌ 302 → `cn.dzmanga.com` → 502 |
| `cn.bzmgcn.com` | ✅ 1211 章 | ❌ 302 → `cn.cnbzmg.com` → 502 |
| `www.baozimh.com` | ✅（跳 `cn.bzmgcn.com`） | ❌ |
| `cn.cnbzmg.com` | ❌ 502 | ❌ |
| `cn.dzmanga.com` | ❌ 502 | ❌ |
| `tw.baozimh.com` | ❌ Cloudflare 挡 | ❌ |

⇒ 详情/搜索**有 3 条路**（其中两条指向同一后端），章节页**所有镜像都是死路** —— 站点侧故障。

### 实现

- 书源配置加 `mirrors`（**App 侧扩展键**，Legado 没有）：顺序就是尝试顺序，主站第一。
- 打开地址一律走 `openComicWithFallback`：每个地址最多试 2 次（重置类错误重试一次常常就好），
  失败按 `mirrors` 换下一个；**"手机没网"直接停**（换镜像没意义，别白等）。
- 失败按描述文本分类：连接被重置 / 连接失败 / 超时 / 域名解析失败 / 手机没网 / 说不清；
  数字码只在描述读不出来时兜底（各平台数字不一致）。
- **只把主文档失败算失败**：图片、统计脚本这类**子资源**失败只计数、不判死（站点广告位天天挂）。
  平台没说清（`isForMainFrame` 为 null）时不算失败，最终由"选择器有没有命中"来判 —— 不让一个
  不确定的错误码背锅。
- 结论里带上波折：`· cn.baozimhcn.com：连接被重置（net::ERR_CONNECTION_RESET）；最后用 cn.bzmgcn.com 打开成功`。

## 八、详情页"章节 0 条"：我拼错了 CSS（1.20.63 / 320）

### 手机端第三次自检

```
· [通过] 搜索（6835ms）命中 77 条，取到书名 77 个、链接 154 个
· [失败] 详情（9228ms）书名「航海王」 · 作者 尾田荣一郎 · 章节 0 条（章节选择器 0 命中）
· [失败] 章节取图（0ms）上一步没拿到章链，跳过了
```

书名、作者都取到了 ⇒ 页面这次**打开成功**（重置没再出现），页面标题也对。卡在章节数。

### 真正的原因

我数章节用的 CSS 是从 `tocUrl` **整条规则**拼出来的：

```
tocUrl = class.pure-u-1-1 … comics-chapters @tag.a@harf@class.comics-chapters__item@text
                                                     ↑ 书源自己的笔误（本意 href）
```

`harf` 既不是取值名也不是合法标签，我的解析器把它当标签，于是拼出
`.…comics-chapters a harf .comics-chapters__item` —— **永远匹配不到**，在真页面上实测 **0 命中**
（作为反面控制组验证过）。所以手机上的"章节 0 条"是必然，不是运气。

书上那句话（"本 App 用详情页的章节链接"）我只做了一半：取链接时确实绕开了笔误，**数章节时却照抄了整条规则**。

### 修法

- 新增 `firstSelectorCss(rule)` —— **只取最前面那一段选择器**，数章节与取章链都用它：
  `.pure-u-1-1.pure-u-sm-1-2.pure-u-md-1-3.pure-u-lg-1-4.comics-chapters a[href]`（真页面 1211 条）。
- `cssFromComicRule` 改成"**前导选择器链**"（遇到取值步就停），并在注释里写明已知限制：
  中段的裸 token 分不清标签与属性，所以 `cssFromComicRule(tocUrl)` 仍会把 `harf` 拼进来 ——
  正因如此，数章节**不许**用它。这两条都写进了用例（含反面断言 `contains('harf')`）。
- 顺带松开时间判据：标题等待从写死的 8 秒改回统一的 `waitTimeout`（25 秒）。
  实测同一次导航重跑就是瞬时的，说明整页响应偶尔会慢十几秒 —— 用紧值会把"慢"误判成"没有"。

## 九、章节取图：我又犯了第三处（1.20.64 / 321）

### 手机端第四次自检（2/3 通过）

```
· [通过] 搜索（411ms）命中 77 条 …
· [通过] 详情（1222ms）书名「航海王」· 作者 尾田荣一郎 · 章节 1211 条   ← CSS 修正生效
· [失败] 章节取图（2771ms）打不开章节页：规则不认识：「.comic-contain amp-img」
  最终地址：https://cn.dzmanga.com/comic/chapter/…/0_1186.html
```

**两条重要信息**：

1. **章节数 1211 在你手机上验证通过** —— 上一版的容器段 CSS 修正是对的。
2. 章节那一步**走到了"读属性"分支**（只有选择器命中数 > 0 才会走到），说明
   **这台手机能打开章节页**（我的浏览器至今仍是 502）—— 站点对国内移动网络与大机房 IP
   表现不同。读图能不能成，就看下面这个 bug 修完后的那一跑。

### 原因：把 CSS 当成书源规则去解析 + 只认 data-src

- 兜底分支里我把 `imageRule`（这是**我拼出来的 CSS**）又交给了 `_extractValues`，
  而那套解析器吃的是 Legado 语法（`class.` / `tag.`）—— 于是报"规则不认识"。
  **页面查询**（CSS）与**书源规则**（配置）是两件事，我在 318 已经为取链接分开过，这里又混了一次。
- 图片属性只读了 `data-src`（书源规则用的就是它，AMP 的惰性属性）。部分镜像把地址直接写在
  `src` 上 —— 于是即便页面有图也取不到。

### 修法

- 兜底改为**直读属性**：先 `data-src`，没有再 `src`；新增 `ComicSourceTarget.attrsOf(css, attr)`
  （取所有命中元素的该属性）。
- **来源必须写进结论**：`（JS 段没给图链，改用元素上的 data-src 直读）` /
  `（…元素上也没有 data-src，改用 src 直读）` —— 三条路的可信度不一样，不许混着说。
- 章节步的失败原因也按"配置错误用原文、网络错误加前缀"分开（前两步早就是这个规矩，这里漏了）。

### 用例（新增 3 条；漫画相关合计 70 条）

JS 段没图链→data-src 直读且写明来源 / 没有 data-src→退回 src 且写明原因 /
两种属性都取不到→如实报 0 张不编造。

**好消息**：章节页在你手机上是**真的渲染出来了**（标题就是章节名）——阅读这条路是通的，
只是我还没取到图。

### 两处错（第四处、第五处）

1. **等待判据错了**：我等的只是"选择器命中"，而 AMP 是**懒加载** —— `amp-img` 占位元素
   先出现、地址后填。于是"元素在、地址空"时，我当场就判了失败（`等 0 秒` 就是这个意思）。
   正确的判据是**等到地址真的出现**（`data-src` 或 `src` 有值）。
2. **描述里写死了"仍 0 命中"**：实际元素是命中的（否则走不到读属性那一步），这句话是假的 ——
   我自己写死的文字，比 bug 更容易把人带偏。现在**命中数按实际写**。

### 修法

## 十一、WebView 返回值要"解掉一层转义"（1.20.66 / 323）

### 手机端第六次自检给的关键证据

```
· [失败] 章节取图（26250ms）等了 25 秒，.comic-contain amp-img 命中 6 个元素，
  但它们的 data-src / src 里都没有地址
  元素实际长这样：\u003Camp-img id=\"chapter-img-0-0\" width=\"1200\" height=\"2133\"
  src=\"https://s1.bzcdn.net/scomic/…/1.jpg\" [src]=\"chapter00Src\" layout=\"responsive\"
  data-src=\"https://s1.bzcdn.n…
```

**这段片子本身就说明了问题**：那个 `amp-img` **明明带着地址**（`src` 和 `data-src` 都有真
URL），而我读出"都没有地址" ⇒ 是我的**取值环节**坏了，不是站点没给。

### 第六处错：WebView 的返回值会再 JSON 编码一层

Android 的 `runJavaScriptReturningResult` 返回的是**再编码一层**的 JSON：字符串里的
`<` 变 `\u003C`、`"` 变 `\"`（片子里的 `\u003C`、`\"` 就是它）。而我几处地方是
`replaceAll('"', '')` 这种"删引号"式处理：

- `JSON.stringify` 出来的数组因为引号被转义 → `jsonDecode` 解出的是**字符串**不是数组
  → 我判 `is List` 失败 → 返回空表 ⇒ "元素有、地址没有"；
- 反过来 JS 段给的 HTML 也因为引号成了 `\"` → 正则 `src\s*=\s*["']` 一律匹配不到。

**根因**：同一个"取值"语义在四个地方各写了一份解析（target 里三份 + 诊断里一份），
彼此对转义的处理还不一样。

### 修法

- 引擎里加**唯一**的解析器 `parseComicJsValue` / `comicAttrList` / `comicText`：
  循环解 JSON（最多三层），字符串解到不是字符串为止；数组/数字/文本都能吃；
  两种平台（Android 编码过 / iOS 直接给原值）**都兼容**。
- target 的 `countOf` / `attrOf` / `attrsOf` / `pageTitle` / `sampleHtml` 全部改走它；
  诊断里的 `_decodeJsonString` 也让它代理 —— 解析只剩一处。
- **片段不再删引号**：`src="…"` 比 `src=…` 有用得多（失败诊断就是给人看的）。

### 用例（新增 6 条；漫画相关合计 77 条）

含"被转义过的数组/HTML"、"没转义的也要能吃"、"空值不许被编造成地址"、
"多一层引号的数字也读成数字"、"片段里引号必须还原"，以及一条端到端：
**JS 段返回被转义的 HTML 时仍要能抠出图链**。

## 十二、上一版把两条**语义不同**的解码并成了一个（回归，1.20.67 / 324）

### 手机端第七次自检：回归

```
结果：0/3 步通过，总耗时 0.3 秒
· [失败] 搜索（259ms）卡片命中 77 条，但书链规则一条都没取到（站点可能改版）
```

和第一次自检**一模一样的症状** —— 这次不是站点，是我上一版改出来的。

### 错在哪

上一版为了"解析只剩一处"，把 `_decodeJsonString` 改成代理 `parseComicJsValue`。但两者**语义不同**：

| | 想拿到什么 | 该解几层 |
|---|---|---|
| `parseComicJsValue`（取值：属性/命中数/标题/片段） | **值**本身（列表 / 数字 / 文本） | 一直解到不是字符串为止 |
| `_decodeJsonString`（`{"values":…}` / `{"text":…}`） | **JSON 文本**，再由调用方按文本抠字段 | 只解**一层** |

引擎脚本都是 `JSON.stringify(...)` 返回 **JS 字符串**，Android 会再编码一层 ⇒
`"{\"values\":[\"…\"]}"`。一路解到底的话，`{"values":…}` 变成 Map，
而取值代码是按**文本**写的 → 抠不出任何东西 → "书链一条都没取到"。

### 修法

- `_decodeJsonString` 恢复"只解一层"（保留 `unescapeJsonString` 的 `\uXXXX` 还原），
  并把**为什么不能合并**写进注释（防止下一个人再"顺手统一"）。
- **假目标改成真机形状**：`androidEncode()` 模拟 Android 那层编码（引号 → `\"`、`<` → `\u003C`）。
  这才是这次回归的根因 —— 以前假目标返回"我以为的形状"，所以单测全绿、真机全红。
- **证明这把锁是真的**：把解码临时改回错法 → 用例失败（复现手机症状）；改回 → 通过。

### 用例

未新增条数，但 77 条全部改在真机形状下跑（值路径 + JS 段路径都过 `androidEncode`）。

### 手机端第八次自检


### 第七处错

书源的 `ruleContent.content` 结尾是 **表达式**：

```js
var imgTags = c.map(item => `<img src="${item.link}">`).join('\n');
    imgTags;        // ← 一个表达式语句，没有 return
```

Legado（Rhino）取的是**最后一条表达式的值**；我却把 JS 段包成 `(function(){ … })()`
—— 没有 `return` 就返回 `undefined` ⇒「JS 段没有返回值」。**这是书源的正常写法，是我的
执行器不兼容**。

### 修法

- JS 段当**字符串**注入，两种写法都支持：
  · `try { __r = eval(__body) }` —— eval 会返回最后一条语句的完成值（表达式式）；
  · 报 `Illegal return statement` 时退回 `new Function(__body)()`（`return` 式）。
- **JS 段失败不再拖死整步**：记下"书源 JS 段没跑通（…），改用元素属性直读"，
  再走直读那条路 —— 真机上正是兜底明明能取到图、却被这个错直接判成失败。

### 真浏览器验证（照手机上的 DOM 形状）

| JS 段写法 | 结果 |
|---|---|
| 表达式式（`imgTags;`） | `<img src="…/1.jpg">` + `<img src="…/2.jpg">` ✅ |
| `return` 式 | `RET-2` ✅ |

### 用例（新增 2 条；漫画相关合计 79 条）

含"脚本必须同时含 eval 与 new Function 两条路"、"JS 段没跑通也要靠属性直读通过"。

### 二、「共 1 话」

两个原因叠加，都是我的：

1. **取目录前没有等**：目录是渲染出来的，页面刚打开就查只数到 0/1 条 → 现在先等容器出现（≤12 秒）。
2. **把 CSS 当书源规则传了**（根因）：`firstSelectorCss` 产出 `.a.b.c`（页面查询写法），而引擎按

- 取字段用**规则原文**（新增 `firstSelectorRule`），等渲染用 CSS —— 注释写明两者不可混用；
- 引擎与 Dart 解析器**都接受"已经是 CSS"的写法**（`.a.b` / `#id`），并加用例锁住。

| 裸 CSS `.pure-u-1-1.…comics-chapters` | **705** ✅ |

（样例标题「番外02 血铸灵丹（下）」、链接带 `chapter_slot=680`，与站点一致。）

## 十六、分类浏览（书源的 exploreUrl + ruleExplore，1.20.71 / 328）

### 书源给的是什么

### 落地的三处

| 文件 | 作用 |
|---|---|
| `comic_json_rules.dart`（新） | JSON 规则子集：`$.a.b` / `$.items[*]` / `$[0]` / `{{$.字段}}` 模板。**缺字段=空串（可选字段），规则写错=报错** |
