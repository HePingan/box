# 漫画源 Step 1：源自检（1.20.60 / 317）

**一句话**：把「包子漫画」这份 Legado 漫画书源当配置装进 App，用手机上的真 WebView 把
**搜索 → 打开一本书 → 打开第一章取图** 跑一遍，逐项给出「通过 / 失败 + 原因」。

这一步不是"能看漫画"，它的价值是**把未知变已知**：章节页在我们两台服务器上都是 502，
只有手机上能问出真相。

---

## 一、为什么架构只能是"App 内 WebView 取页"

实测证据（2026-09-27，两台机房机器 175 / hpa888 都试过）：

| 环节 | 实测结果 | 说明 |
|---|---|---|
| 搜索页 | **HTTP 403 + `__gatekeeper_challenge`** | 纯请求过不去；两台机房 IP 一律 403 |
| 搜索页（真浏览器） | ✅ 挑战能过，`.comics-card` 命中 **77 条** | 真实 DOM 与书源类名完全对得上 |
| 详情页 + 章节列表 | ✅ | 标题「航海王」，章节 **1211** 条 |
| 分类接口 | ✅ `/api/bzmhq/amp_comic_list` 200 JSON | |
| 封面图 | ✅ **无防盗链**（不带 referer 也 200，33KB jpeg） | `Image.network` 能直接取 |
| **章节阅读页** | ❌ **一律 502** | 更换镜像域名、从详情页点击进入（带 Referer + cookie）都一样 |

⇒ **服务端代取不可行**（JS 挑战 + 机房 IP 502，两处都是死穴）。
⇒ 唯一可行路径：**App 内的 WebView**。它既能过挑战，又能跑书源里的 `<js>` 段 ——
Dart 没有 JS 求值能力，WebView 有（Legado 自己也是这么干的）。

## 二、这一步做了什么（代码位置）

| 文件 | 作用 |
|---|---|
| `lib/features/comic/domain/sources/seed_comic_source.dart` | 书源 JSON 原样内置（**配置数据**，Step 4 改成可热更新） |

| `lib/features/comic/domain/comic_source_engine.dart` | 在**页面里**跑的规则解释器（JS）+ `java.*` 垫片 |
| `lib/features/comic/domain/comic_source_diagnostics.dart` | 自检流程：三步、逐步给结论、每步带页面标题与最终地址 |
| `lib/features/comic/presentation/comic_source_webview_target.dart` | 真机取数：驱动一个**离屏 1×1 WebView** |
| `lib/features/comic/presentation/comic_source_check_page.dart` | 自检界面 + **「复制结论」**（手机上贴回来就是证据） |
| `lib/features/comic/presentation/comic_library_page.dart` | 漫画库右上角加「源自检」入口；**删掉那句假文案** |

坏文案（原来）：「在线漫画源请到扩展页安装」—— 扩展页里根本没有漫画源可装（全仓无此扩展点）。
现在指向真的能用的东西：「在线漫画源还没接入 —— 右上角「源自检」可以看看内置源在这台手机上通不通。」

### 界面上的三条硬规矩

1. **每步失败必须写原因**：超时 / HTTP 状态 / 选择器 0 命中 / 规则不认识，四类分开说；
   还会把**页面标题**带出来 —— 502 这种错误只看"命中 0"是看不出来的。
2. **配置错误 ≠ 站点没数据**：规则解析不了会说「规则不认识：「…」—— 这是配置问题，不是站点问题」，
   不会被混进"打不开页面"里带偏排查方向。
3. **跑到一半就失败**：后两步标「跳过」，不是「通过」；拿到图就当场显示一张（能显示 = 图片链通）。

## 四、规则引擎：支持到哪、哪里不一样（不藏着）

支持（这份源真实用到的形状）：
- 选择器：`class.a b c`（**同一元素**上的多个类名）· `tag.amp-img` · `id.x` · 裸标签名 `amp-img`；
- 索引：`class.x.0`、`tag.amp-img.0`、单独一段 `.0`；
- 分段：`@` 分隔，逐段往里找（后代）；
- 取值：`text` / `html` / 属性名（`src` / `href` / `data-src` …）；
- **JS 段**：`<js>…</js>` 与 `@js:…` 在页面里真跑，配套 `java.*` 垫片（`getElements` / `t2s` / `baseUrl`）。

**明确没做**：
- `java.t2s` **繁转简未实现**（没词表），拿到的繁体就是繁体 —— 界面上写了这句，不冒充已转换；
- 这份源的 `ruleBookInfo.tocUrl` 第 3 段是**它自己的笔误**（`@harf@`，应为 `@href@`）：
  本 App 不照抄，章节链接改从详情页取（实测 1211 条正常）；
- Legado 的其它语法（正则、模板变量、`ajax`、登录态等）不在范围内。

## 六、真机实测与修正（1.20.61 / 318）

### 手机端第一次自检结果（1.20.60/317）

```
结果：0/3 步通过，总耗时 2.0 秒
· [失败] 搜索（1983ms）卡片命中 77 条，但书链规则一条都没取到（站点可能改版）
  页面标题：海贼 搜索 - 包子漫画
· [失败] 详情（0ms）上一步没拿到书链，跳过了
· [失败] 章节取图（0ms）上一步没拿到章链，跳过了
```

**好消息**：挑战过了 —— 页面标题、最终地址、卡片 77 条都是真的，"手机上的 WebView 能不能过 WAF"这条未知**解决了**。

**坏消息是我自己的 bug**：引擎把规则最后一段 `href` 当成了类选择器 `.href` 去找，
于是书链一条都取不到。原因是 JS 引擎里「取值步」的判断写在了「选择器步」**后面**，
而 Dart 侧写的是前面 —— 两边语义打架。已在真页面上复现并修正（取值步先判；裸 token 按标签算）。

> 教训：规则解析的**判断顺序**就是正确性本身。现在两边同序，并且加了源码级回归锁
> （断言 `VALUE_HOLDERS` 的判断出现在 `buildCss` 之前），不只锁行为。

### 修正后在真页面上的实测（同一段引擎 JS，在真浏览器的真 DOM 上跑）

| 规则 | 结果 |
|---|---|
| 搜索 `name` | ✅ 77 条（海贼王 / 海贼王yellow / …） |
| 搜索 `bookUrl` | ✅ `…@tag.a@href` → `/comic/haizeiwang-weitianrongyilang` |
| 搜索 `coverUrl` | ✅ 封面地址（需 per-item 作用域，Step 2 再做） |
| 详情 `name` / `author` | ✅ 航海王 / 尾田荣一郎 |
| 详情章节列表 | ✅ **1211** 条，首章 `…/user/page_direct?…chapter_slot=1186` |

### 章节页 502：是站点侧，不是我们

三种客户端、多个镜像都试过：

| 试法 | 结果 |
|---|---|
| 真浏览器（**同一个**刚过挑战的浏览器） | 502（跳到 `cn.dzmanga.com` 后 nginx 502） |
| curl（构建机） | 302 → `cn.cnbzmg.com` → **502** |
| 换镜像 `cn.bzmgcn.com` / `cn.dzmanga.com` / `tw.baozimh.com` | 502 / 502 / 403 |
| 换章节（1187） | 同样 302 → 502 |

⇒ **章节阅读页整条路由现在是挂的**（nginx 上游死），与手机、与机房 IP 都无关。
所以：Step 2（搜索/分类/详情/章节列表）**现在就能做**；Step 3（在线阅读）要等站点恢复。
自检界面里对 502 的说明也改准了：写清"站点这一侧上游挂了，换网络换手机都一样"。

## 七、取页健壮化：镜像回退 + 重试（1.20.62 / 319）

### 手机端第二次自检暴露的问题

```
· [通过] 搜索（272ms）命中 77 条，取到书名 77 个、链接 154 个
· [失败] 详情（1278ms）页面加载出错（-6 net::ERR_CONNECTION_RESET）
```

搜索页能开、**同一个域名**的详情页却被重置 ⇒ 不像域名被墙，更像"这一跳被打断"。
所以做的不是"绕过"，而是**重试 + 换镜像**，并且把波折如实报出来。

### 镜像的真实可用性（真浏览器逐个试，2026-09-27）

| 镜像 | 详情页 | 章节页 |
|---|---|---|
| `cn.baozimhcn.com`（源里的主站） | ✅ 1211 章 | ❌ 302 → `cn.dzmanga.com` → 502 |
| `cn.bzmgcn.com` | ✅ 1211 章 | ❌ 302 → `cn.cnbzmg.com` → 502 |
| `www.baozimh.com` | ✅（跳 `cn.bzmgcn.com`） | ❌ |
| `cn.cnbzmg.com` | ❌ 502 | ❌ |
| `cn.dzmanga.com` | ❌ 502 | ❌ |
| `tw.baozimh.com` | ❌ Cloudflare 挡 | ❌ |

⇒ 详情/搜索**有 3 条路**（其中两条指向同一后端），章节页**所有镜像都是死路** —— 站点侧故障。

### 实现

- 书源配置加 `mirrors`（**App 侧扩展键**，Legado 没有）：顺序就是尝试顺序，主站第一。
- 打开地址一律走 `openComicWithFallback`：每个地址最多试 2 次（重置类错误重试一次常常就好），
  失败按 `mirrors` 换下一个；**"手机没网"直接停**（换镜像没意义，别白等）。
- 失败按描述文本分类：连接被重置 / 连接失败 / 超时 / 域名解析失败 / 手机没网 / 说不清；
  数字码只在描述读不出来时兜底（各平台数字不一致）。
- **只把主文档失败算失败**：图片、统计脚本这类**子资源**失败只计数、不判死（站点广告位天天挂）。
  平台没说清（`isForMainFrame` 为 null）时不算失败，最终由"选择器有没有命中"来判 —— 不让一个
  不确定的错误码背锅。
- 结论里带上波折：`· cn.baozimhcn.com：连接被重置（net::ERR_CONNECTION_RESET）；最后用 cn.bzmgcn.com 打开成功`。

### 用例（本轮新增 9 条；漫画相关合计 66 条，全量 3802）

主站被重置→换镜像成功且写进结论 / 第一次重置重试成功要说"第 2 次才成功" / 手机没网只试一次就停 /
所有候选都失败要列出每个地址的错 / 错误分类六种 / 数字码兜底 / 候选地址顺序去重（相对与完整地址）/
内置源配了镜像且第一个是主站。
