# 全屏播放器控件：五处排版瑕疵与修正（2026-10-19）

> 触发：用户贴了一张真机全屏截图，问"这里有什么瑕疵"。
> 方法：**逐像素量**截图（2800×1260 @3x = 933×420dp），再对照
> `lib/video/widgets/player/custom_video_controls.dart` 的实现，不靠观感判断。

## 一、实测到的五处问题

| # | 问题 | 实测证据 |
|---|---|---|
| 1 | 顶栏渐变没铺满，左右各留一条纯黑 | `y=28` 那行从 x=133 的亮度 **0** 突跳到 x=140 的 **9.3**；`margin: fromLTRB(10,8,10,0)` 让渐变只铺在中间 |
| 2 | 底部面板左右边距差约 4 倍 | 面板 bbox `x 132…2770` → 左边距 **132px(44dp)**、右边距 **29px(10dp)** |
| 3 | 面板底边几乎贴住屏幕 | 面板底 y=1238，屏高 1260 → 只剩 **21px(7dp)** |
| 4 | 播放键形状与其余按钮不一致 | 播放键 **52×44 圆角18**；其余 **40×38 圆角18** |
| 5 | 时间胶囊与进度条几乎贴住 | 轨道两端 Padding 只有 8dp |

另有一条**不需要改**的观察：`CustomVideoControls.episodeName` 被传入但 `_buildTopBar`
从不渲染它 —— 这是代码注释里写明的"顶栏视觉降噪，移除副标题"，
属于设计取舍，**本轮未动**。要显示"第几集"另行决定。

## 二、改法

### 1. 顶栏渐变铺满整宽

`_buildTopBar` 拆成两套外壳：

* **全屏**：外层 `width: double.infinity` 铺满，渐变三段
  （0.78 → 0.30 → 0.0，stops 0/0.45/1），左右留白交给**内层 Padding**；
* **内嵌**：维持原来的实色条（跟着播放器圆角走，不整宽拉伸）。

内容行抽成 `_buildTopBarContent()` 由两种外壳共用 —— 否则会出现两份重复的 Row。

顺带给标题加 `height: 1.0`：14px 的字在 30px 圆钮旁边原本看起来偏上。

### 2. 底部边距/留白

* 左右仍是 8dp（对称）；**底部 6 → 14dp**（原来只剩 7dp，手势条会压到按钮）；
* 内层底 padding 4 → 6dp；
* 时间胶囊与轨道之间的水平间距 8 → **12dp**。

### 3. 按钮形状统一

`_glassButton` 改为**宽高相等**：

* 全屏：全部 **40×40、圆角 20（正圆）**，播放键只靠底色与图标大小（26 vs 22）强调；
* 内嵌：全部 **32×32、圆角 16（正圆）**。

原先播放键是 52×44 方角，一排六个里它既大又是方角，视觉重量失衡。

## 三、怎么验的（不是靠看图）

新增 `test/video/fullscreen_controls_layout_test.dart`，用 video_player 上游测试里
的 `FakeController` 喂给真控件渲染（不需要平台通道、不解码视频），量真实几何：

1. 返回键左边缘 = 10dp（≤1.5dp 误差）；
2. **像素级**：顶栏高度内一行，左边缘亮度不得低于中间 4 以上；
3. 播放键与其余按钮同宽同高（≤0.5dp），且宽高相等（正圆）；
4. 进度条占满中段（两端各让 12dp）；
5. 底栏离屏幕底 ≥ 12dp。

**做了反向对照**（避免写出永远绿的用例）：

* 把顶栏 margin 还原 → 第 1 条断言变红（`Actual: 20.0`）；
* 只还原 margin、内层 padding 减 0 → 第 2 条像素断言精确复现原缺陷：
  `顶栏左边缘亮度 0 明显低于中间 10`。
