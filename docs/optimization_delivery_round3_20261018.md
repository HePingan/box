# 第三轮：旧漫画书迁移（2026-10-18）

> 承接 `optimization_delivery_round2_20261017.md` 的待办第 1 条。
> 本轮用 3 个并行 agent 分工（domain / presentation / 集成与验证）。

## 一、问题

旧版把 CBZ/ZIP 的页图解压到**系统临时目录**，而 `ComicBook.pages` 是长期引用。
系统清临时目录（低存储、重启清理）之后：

- 书架上的书还在
- 点开每一页都是白页（破图标）
- 备份只存元数据、不存图片 —— 用户以为自己有备份
- 用户没有任何线索知道"为什么坏、怎么办"

第二轮已让**新导入**的书落在文档目录，但**老书**仍然指着被清掉的临时目录。

## 二、这轮做了什么

### domain：`comic_page_health.dart`

只体检**本地书**（在线书的页在站点上，本机没有文件）。每本只抽头/中/尾最多 3 页
`stat` 一次 —— 导入器把一本书的所有页放在同一个目录、系统清理是整目录消失，
所以抽样与全扫**等价**，一本几百页的书不会被拖慢。

两条刻意的保守设计：

| 判断 | 理由 |
|---|---|
| 任一采样页还活着 → 判健康 | 宁可漏报，也不误杀一本好书 |
| 探针抛异常 → 按活着处理 | 失败安全，不能因为 stat 出错吓唬用户 |

`ComicPageHealthNoticeStore` 把「这台设备已经告诉过用户」存进独立 `CacheStore`，
**不写进 ComicBook**：换设备该重新提示一次，备份导出也不该带出本机状态。

### presentation：书架顶部内联提示条

不是弹窗 —— 不拦截操作，书照常可读。说明三件事：几本、为什么、怎么办。

文案**诚实**：重新导入会新增一本，确认内容一致后手动删旧的。刻意**不做**按标题
自动匹配（`filePath` 可能被改名/换包，猜错会删掉好书）。

没有坏书时组件零高度，不占位。

### 集成时修掉的两个问题

1. **API 名字对不上**：两个 agent 独立工作时，UI 侧假设 `health.affectedBookIds`，
   domain 实际提供 `missingBookIds`。集成时修正。
2. **注入 probe 会绕过「已提示过」过滤**（我自己第一版的缺陷）：导致测试里
   「暂不处理」的持久化根本没被走到。改为 probe 只替换**判定**这一步，
   「是否已提示过」两条路共用同一套过滤。

## 三、验证

| 项 | 结果 |
|---|---|
| `flutter analyze` | **10 issues**（与基线一致，零新增） |
| 全量测试 | **4605 通过 / 3 跳过 / 0 失败**（本轮起点 4561） |
| 新增测试 | 44 条（domain 27 + 呈现/接线 17） |

关键测试锁住的行为：

- 点过「暂不处理」后**整页重建**也不再提示（跨进程记忆，不是进程内 bool）
- 坏书被删掉后提示条自动消失
- 判定为空时不往存储里写任何东西
- 「重新导入」走既有导入流程，不自创一条

### 一个测试环境限制（已写进代码注释）

`testWidgets` 跑在假时钟里，**真实 `File.exists()` 的 Future 永远不完成**
（实测会挂到 10 分钟超时）。所以 widget 测试用注入探针替换判定这一步，
真实 IO 只在真机验证；判定本身在 domain 测试里用注入探针覆盖。
