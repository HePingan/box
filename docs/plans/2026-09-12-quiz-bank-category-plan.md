# Box 题库分类（多题库）改造方案

> 状态：**待拍板（先方案，不写码）** · 2026-09-12
> 范围：47.109.97.1 题库后台（服务端 `server.dart`）+ Box App（管理端题库 tab & 客户端题库页）
> 结论先行：**能做**。三端已有「分类」最小闭环，但直接导入第二个题库会踩 7 个缺口，其中 3 个会直接破坏「拉取不受影响」。建议先补 A 组缺口，再导入新库。

---

## 1. 需求与术语

需求（用户原话归纳）：

1. 已有第二个题库要入库，后台管理的题库要能按「题库分类」管理；
2. 改完后**不影响** Box App 的题库查看与拉取；
3. 客户端拉取时可**选择题库**（分类）进行拉取。

术语对齐（全篇）：

- 「题库分类」= 服务端题目对象上的 `category` 字符串字段；**一个非空分类 = 一个可订阅、可单独拉取的“题库”**；
- 客户端「分类订阅」对话框 = 选择要拉取的题库入口（已存在，见 §2.3）；
- 分类是单层字符串，未来若要「大库/子科目」两层，用 `A/B` 命名即可，不动 schema。

## 3. 缺口与修复（A = 低风险先做，B = 拍板后按需）

### A1 变更窗口裁剪无保底 —— 大导入后「新装机 / 全量重拉」丢题【最高优先 · 服务端】

- 证据：server.dart:5268 裁剪规则「只留最新 5000 条」，无任何保底。
- 实测模拟（以现网数据为基础、按“导入 N 条新题=追加 N 条变更”推演）：

| 导入规模 | 新窗口起点 | 全量重拉会丢的已发布题 |
|---|---|---|
| +500 | 1729 | 0 / 3532 |
| +1000 | 2229 | **228 / 3532** |
| +1500 | 2729 | **569 / 3532** |
| +2000 | 3229 | **861 / 3532** |
| +3000 | 4229 | **1632 / 3532** |
| ≥5000 | — | 旧库整库不可达 |

- 影响：存量用户增量同步不受影响；但**新装机、重装、点了「全量重拉」的用户**会拿不到旧库题目（表现＝“同步过却搜不到题”）。这正是「不影响拉取」的核心威胁，且**导入新库这个动作本身就会触发**。
- 修复：裁剪时**保护「每题最后一条变更」**（保底 = 5000 条 + 题数条；只裁中间历史）。由此任一客户端从 cursor=0 重走都能收敛到每题的最终状态（含归档题的 delete 标记），不需要新增全量快照接口。旧客户端无需改动即受益。
- 测试：服务端 E2E —— 造 >5000 变更后断言“每道 published 题仍可在窗口中找到最后变更”；fresh 拉取（cursor=0）能拿到全部题 id。

### A2 delete 变更字段名不匹配 —— 下架/删除不回传客户端【真 bug · 客户端】

- 证据：线上 `/api/quiz/sync` 实测，delete 条目为 `{sequence, questionId, operation:'delete', changedAt}`（无 `id` 字段）；
  客户端读的是 `change['id']`（`quiz_cloud_sync.dart:108`）→ 永远为空 → **删除被静默跳过**；
  而 App 侧单测夹具写的却是 `{'operation':'delete','id':'cloud-q1'}`（`test/quiz_cloud_sync_test.dart:104`）→ 测试一直绿、线上一直坏。
- 影响：服务端归档的 79 题，在客户端永远不被清理（“云端题库下架”不生效）。
- 修复：客户端改为读 `questionId`（保留 `id` 兜底）；单测夹具**改成真实报文形态**并加回归用例。
- 备注：修好前已发出的旧版本客户端拿不到删除，属可接受残留（下架频率低）；不做“服务端双写 id”避免双事实源。

### A3 分类「只填空白、不覆盖」—— 后台改分类后老客户端分类陈旧【客户端】

- 证据：`quiz_bank.dart:1448` 仅 `oldCategory.isEmpty && newCategory.isNotEmpty` 时写入。
- 影响：管理端重分类 / 改名后，存量客户端本地分类**不更新**，分类筛选显示旧分类。
- 修复：云端非空且与本地不同时**覆盖**（客户端没有本地改分类入口，无冲突源；本地编辑的题已另存为新 id，不受影响）。

### A4 订阅名失效不收敛 —— 分类改名/合并后老订阅静默空拉【客户端】

- 证据：`pullAll` 直接按订阅名单同步（`quiz_cloud_pull.dart:126-138`）；`fetchCatalogs` 只在“订阅为空”时全订（:92-104），**不处理“订阅了已不存在的分类”**。
- 影响：分类改名后，用户点「更新」看似成功、实际 0 新增（旧名无变更、新名未订阅）；「全量重拉」同样空转。
- 修复：拉取时对账「订阅 ∩ 云端目录」；消失的分类按拍板项 1 处理；新增分类按拍板项 2 处理。

### A5 管理端缺「分类筛选」和「全选」—— 整库改名/归并不可行【客户端】

- 证据：筛选维度枚举无 category（`quiz_bank_filter.dart:5`）；列表无全选（part:1957 只在待审核弹窗）。
- 影响：3385 题的库要改名/归并，得逐题长按选择，不可行；也看不到“每库多少题”。
- 修复：
  1. 筛选 sheet 加「分类」维度（先例：状态/图片/题型），列表 chip 同步支持；
  2. 多选条加「全选当前筛选结果」（带确认弹窗，显示数量与目标分类）；
  3. 这样“整库改名”= 筛选分类 → 全选 → 批量设新分类，复用现有接口，零新增 API。

### A6 导入无默认分类 —— 新题库不带分类时全部落空分类【服务端 + 客户端】

- 证据：导入弹窗无分类输入；条目缺 category 即空串。
- 影响：**空分类题在“按分类同步”下不可达**（服务端过滤 `question.category == category`，空 ≠ 任何分类）——现存 147 道就是例子：只要用户订阅过分类（拉取后自动全订非空分类），就永远不会拉到它们。
- 修复：
  1. 导入接口 body 增加可选 `defaultCategory`，**条目自带分类优先、缺省用默认值**（向后兼容）；
  2. 导入弹窗加「默认分类」输入框（预填上次使用值）。

### A7 存量 147 空分类题 + 硬编码默认值【数据迁移 + 客户端】

- 证据：157 道空分类题（147 published / 8 archived / 2 pending），来源均为 OCR 录入（插件侧截屏录题）。**在“按分类同步”下不可达**——客户端按订阅分类逐个同步，空分类题不属于任何分类；且这些题在服务端变更窗口里位置最旧，一旦执行大导入/整库重分类把窗口推进，它们会最先被裁掉（实测：整库重命名后其中 77 道丢失窗口）。
- 修复：把 147 题回填到明确分类（归属见拍板项 3）；**回填操作本身会把它们重新推入窗口尾部**，所以「回填」应紧跟 A1 修复或与整库重分类同一批执行，避免先裁后补。
- 管理端两处硬编码 `'驾驶理论题库-20260719'` 改为「上次使用 / 可空」。

### B 组（拍板后再定，不阻塞新库导入）

- **B1 分类级操作端点**：`/admin/quiz/categories/rename {from,to}`（原子改名/合并，免传上万 id 列表）。A5 落地后按需再上。
- **B2 「分类订阅」交互打磨**：文案、题量展示、保存后可选“立即拉取”；入口维持单一（云端卡片），不新增悬浮按钮。
- **B3 管理列表服务端分页**：当前 fetchAll 全量下发、客户端过滤；题量到 1 万+（响应 ~4MB）再改。
- **B4 文案统一**：「分类订阅」是否需要改成「题库订阅 / 选择题库」贴合心智（拍板项 6）。
