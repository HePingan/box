# 服务器运维插件（server_ops）下一步优化方案

线上基线：**1.20.32 (289)**，插件已是内置插件（首页「服务器运维」，三页签：服务器 / 文件 / 终端）。
本方案基于 **289 的代码 + 2026-09-25 对运维通道的真实探测**，行号均已回读核对。

### 运维通道真实能力（curl 实测，2026-09-25）

| 能力 | 结果 | 对方案的含义 |
|---|---|---|
| PROPFIND 属性 | `getlastmodified` / `getcontentlength` / `getcontenttype` / `getetag` / `displayname` / `resourcetype` + lock 相关 | **没有 unix 权限/属主属性** → 「权限列 + chmod/chown 面板」靠 WebDAV 做不到 |
| 文件 COPY | `201` ✅ | 「复制文件」可做，服务端完成不耗流量 |
| 目录 COPY | `201` 但**副本里是空的**（Depth:1 只回 1 个 href） | 目录复制**必须客户端逐文件**做；直接用 COPY 会静默丢内容 |
| Range 下载 | `206` ✅ | 断点续传可行 |
| 特殊字符文件名（中文 / 空格 / `+` / `#` / `%`） | 正确百分号编码后 PUT 全 `201`，服务端存回原名 ✅ | 客户端编码走 `webdav_client.dart:176 encodeRemotePath`，但**缺 live 用例** |
| PROPPATCH | `207`（rclone 不持久化自定义属性） | 别用 WebDAV 属性当存储 |
| MOVE（含改名） | ✅ 但 `Overwrite: F` 不实现（目标已存在仍 201 覆盖） | 覆盖保护只能靠客户端 `exists()` 预检（既有约定，保持不变） |

## 二、路线分组

### A 组：低风险体检项（一组做完一次发版就能感知）

**A1. 设置页加「测试连接」三联（DAV / 终端 / 快照）—— 如果本轮只做一件事，做这件**

- 现状：设置只存地址与口令（`server_ops_settings.dart:60,63`），没有任何"连得上吗"的自检；连接失败只体现在页面报错里，用户和我都只能猜。
- 机制：DAV 通了不代表终端通（终端的 Basic 认证是 WebView 层应答，`terminal_tab.dart:83`），快照是第三个独立端点（`host_service.dart:41-67`）。三者失败原因完全不同，必须分开报。
- 改动：底部弹层加三个按钮，各跑一条最小请求（DAV：列根目录；终端：对 `/term/` 发一条 HEAD/握手；快照：拉一次 hosts.json），逐条给出人话结论与原始状态码。
- 收益：把**上一轮欠下的"终端页真机未验证"**从"说不清"变成面板上的一个可复现结论；真机出问题时反馈里自带状态码。
- 成本：0.5 天。验收：单测覆盖三路各自的成功/失败/超时；真机跑一次把结论贴回本文件。

**A2. 上传：多选 + 串行队列 + 可取消**

- 现状：`files_tab.dart:171` 单选一次传一个；传输中只有底部进度条，没有取消。
- 机制：`_runTask` 是"一个任务一段 busy"的模型，批量需要队列；取消需要 `TransferCancelToken`（远端存储插件已有实现，运维通道这边没用）。
- 改动：走 `pickFiles(multiple)` → 串行队列（并发=1，避免占满手机上行）→ 每项可取消、可跳过失败继续；队列界面显示 `第 i/n`。
- 收益：一次传多张截图/日志，失败不打断整批。
- 成本：1 天。验收：假服务断言并发恒为 1、取消后不再发起后续 PUT、中间失败后仍继续下一项。

**A3. 文件列表：排序 + 过滤 + 多选批量删除**

- 现状：列表只按服务端返回顺序，无排序/搜索/多选。
- 机制：`_entries` 已是本地列表（`files_tab.dart:41`），排序与过滤纯客户端即可；批量删除只是把 N 次 `delete()` 串起来。
- 改动：名称/大小/时间三档排序、关键词过滤、长按进入多选（批量删除 / 批量移动），删除仍保留二次确认且文案写明不可恢复。
- 收益：`/root` 下几十个文件时是刚需（宝塔同类功能的默认体验）。
- 成本：1 天。验收：widget 用例覆盖排序三档 + 过滤 + 多选删除计数。

**A4. 复制 / 移动到…**

- 现状：只有改名（同目录换名），没有跨目录移动与复制。
- 机制：文件 `COPY` 实测可用（服务端完成，不耗流量）；**目录 COPY 会得到空目录**，必须客户端递归逐文件 COPY 并显示进度。
- 改动：行菜单加「复制到…」「移动到…」（目录选择器复用面包屑/目录列表）；目录操作明确标注"逐文件进行，可取消"。
- 收益：宝塔式整理文件的核心操作；跨目录移动比"下载+上传"快一个数量级。
- 成本：1 天（含"空目录陷阱"的防呆与用例）。验收：live 用例断言目录复制后子文件真的存在（这条正是本轮实测暴露的坑）。

**A5. 特殊字符文件名的 live 契约测试**

- 现状：live 用例只覆盖普通文件名（`test/.../ops_webdav_live_test.dart`），编码函数 `webdav_client.dart:176` 没有针对 `空格 / + / # / %` 的回归保护。
- 机制：这些字符一旦漏编码，真机表现为"上传成功但列表里名字变了"或 400，属于最难自查的一类。
- 改动：live 用例加一轮 `运维 测试 +.txt`、`a#b.txt`、`a%25b.txt` 的 PUT→PROPFIND→GET→DELETE 往返。
- 收益：把本轮 curl 实测的结论固化成回归测试。
- 成本：0.5 天。验收：`flutter test --tags live` 全绿（缺凭据时自动 skip）。

**A6. 终端页：复制/粘贴辅助栏 + 断线重连 + 字号**

- 现状：只有 WebView + 「重新加载」（`terminal_tab.dart:83,122`）；手机上 Ctrl / 方向键 / 粘贴无入口，WebSocket 断了只有白屏。
- 机制：ttyd 前端能收 `Ctrl-*` 组合；辅助栏就是在 WebView 里注入按键；断线检测用 `onWebResourceError` + 心跳。
- 改动：底部一排 `Ctrl / Tab / ↑↓←→ / 粘贴`，断线时给人话提示与「重连」，设置里加字号。
- 收益：终端从"能看"变成"能用"（改配置、重启服务这些真要敲键）。
- 成本：1 天。验收：真机截图三个操作各一次（这条必须真机，WebView 上不了单测）。

**A7. 主机指标扩字段：磁盘 IO / Swap / 温度**

- 现状：服务器页只有 CPU / 内存 / 磁盘 / 负载 / 运行时长 / 网络速率（`host_tab.dart:347,356,367,380,384,387`）。
- 机制：采集器 `tool/gen_hosts_json.py` 读 `/proc`，加字段 = 改脚本 + 部署到 175（cron `*/2`）+ 客户端解析容错（老快照缺字段必须仍能渲染）。
- 收益：判断"是不是磁盘打满/在换页"这类真实故障，现在缺的正是 IO 与 Swap。
- 成本：1 天（含 175 部署与老快照兼容）。验收：单测覆盖缺字段的老快照；175 上 `--collect` 跑通。

**A8. 下载残留清理**

- 现状：下载一律写 `getTemporaryDirectory()/原名`（`files_tab.dart:197`），同名覆盖、旧文件长期留占空间。
- 机制：临时目录不清理；手机上表现为"空间莫名变少"。
- 改动：下载前清理同名旧文件；提供"清空下载缓存"入口（与既有「清缓存」并列，后者见 `host_tab.dart:88`，那份清的是快照与历史，两者不要混）。
- 收益：避免"看不到的垃圾文件"。
- 成本：0.25 天。验收：单测断言同名文件被替换。

### B 组：已承诺项与结构项

**B1. 多服务器模型 + 175 接入（文档已承诺，代码零实现）**

- 现状：文件页/终端页只连一台（设置里单个 `baseUrl`/`terminalUrl`）；服务器页已是多机。
- 机制：宝塔式体验的关键是"选机器"，而文件与终端要按机器切换连接。175 没有 443 与证书，既有约定是 SSH 隧道把它的回环 DAV 挂到 hpa888，再用 `^~ /dav175/` 暴露（不新增域名/证书）。
- 改动：① 服务端：隧道 + nginx location（同时把 `/term175/` 一起考虑，否则只有文件能切、终端不能）；② 客户端：设置里从"一套连接"改成"每台机器一条连接"，文件页/终端页加机器切换器。
- 收益：两台机器一个 App 管全，和宝塔APP 的形态一致。
- 成本：3–5 天（服务端 0.5 天，客户端结构改动为主）。验收：live 用例对 `/dav175/` 跑通根目录列举；真机在两台机器间切换各做一次写操作。

**B2. 主机历史服务端化**

- 现状：折线历史是客户端环形缓冲（装上才开始攒，换设备就没了）。
- 机制：175 每 2 分钟已产出快照，顺手落 JSONL 就能有 24h/7d；App 只读。
- 改动：生成器加落盘 + 保留策略，边缘机暴露一个聚合端点；客户端历史优先读服务端、缺则回落本地。
- 收益：新装即有历史曲线，多设备一致。
- 成本：1–2 天。验收：端点返回条数/时间窗正确；客户端渲染回归。

### C 组：单独立项（要动安全模型或服务端）

**C1. 凭据模型（本轮最高优先级，建议随 A 组一起发）**

- 现状：运维通道口令（等同服务器 root：整盘读写 + root shell）**被构建注入进 APK**（已实测：`libapp.so` 里口令字节计数 0→1），而 APK 是**公网可直接下载**的。任何人下载 289、反编译取字符串，就拿到你们服务器的 root 权限。这不是理论风险。
- 机制：静态 Basic 口令 + 公开产物 = 凭据公开；且 /term/ 是公网可达的 root shell。
- 改动三档（可叠加）：
  - **立即档（0.5 天）**：服务端口令轮换脚本 + 文档化流程；App 设置页写明"此口令等同服务器 root，勿外传 APK"。
  - **中期档（1–2 天）**：APK 不再内置口令 → 首次由用户输入，存本机加密（Keystore）。需要新依赖（`flutter_secure_storage`）或自写 Keystore 包装；这会打破"不新增依赖"的旧口径，需要你点头。
  - **根治档（3–5 天）**：服务端代理（C2）。App 只带"设备令牌"，服务端做路径白名单 + 审计 + 限流 + 可撤销。**宝塔式功能（进程/服务/日志/权限/解压）唯一可行前提就是它。**
- 收益：把"APK 即 root"变成"APK 只是个客户端"。
- 成本：见三档。验收：立即档=轮换后旧口令失败、新口令可用；中期档=APK 内 grep 不到口令字节（AOT 标记计数法直接验）。

**C2. 服务端受限执行 API（宝塔式能力的载体）**

- 现状：只靠 WebDAV，实测**拿不到权限/属主**，也就没有进程列表、服务重启、日志 tail、chmod、解压、目录大小。
- 机制：这些都要服务端执行命令。做法是一个小的 FastAPI 服务（可复用 `box-update-server` 的既有骨架与本机运维约定），只暴露**白名单动作**（查看类 + 少量受控写操作），全部落审计。
- 收益：插件从"文件管理器 + 终端"升级成"服务器面板"。
- 成本：3–5 天（含审计与白名单）。验收：白名单外的命令一律拒绝且有审计记录；每类动作有 live 用例。

**C3. 阈值告警推到飞书**

- 现状：只有人打开 App 才看到指标（与既有 Kuma/Feishu 告警体系是两条线）。
- 机制：175 采集时判阈值（CPU/内存/磁盘/离线/关键服务 down），经现有 Feishu 通道推送。
- 收益：不用盯着 App。
- 成本：1 天。验收：造一次假阈值触发，飞书收到且不重复轰炸（含静默期）。

## 三、明确不做

| 不做 | 理由 |
|---|---|
| 接宝塔面板 API | 权限等同 root（写任意文件 + 执行命令），key 进 APK 即失守；既有结论，不重开 |
| 权限/属主列 + chmod/chown 面板 | 运维通道 PROPFIND **不返回** unix 权限属性（本轮实测）；要做必须先有 C2 |
| PHP / 网站 / 数据库 / 防火墙管理 | 不是这个 App 的场景（那两台机器上没有这些负载） |
| 文件列表缩略图 | 远端缩略图要整图下载，几百张图的目录会狂吃流量；除非 C2 提供服务端缩略图 |
| 客户端打包/解压后上传 | 大包要过手机上行，不现实；服务端解压属 C2 |
| 把 /term/ 换成非 root 用户 | 用户明确要 root shell；改这个等于改需求，不做，但风险写进 C1 |
