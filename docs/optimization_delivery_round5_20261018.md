# 第五轮：那条偶发失败的测试（2026-10-18）

> 承接第四轮待办第 1 条。**结论：它不是测试问题，是一个真实的安全缺陷。**

## 一、现象

`test/utils/local_secret_codec_test.dart` 在全量跑批时偶发失败（约 0.3% 的跑批），
单独跑、目录跑都稳定通过。失败点是这一句：

```dart
// 盐不对 → 解不出来（不会拿错盐的密钥解出垃圾）
expect(LocalSecretCodec.decryptLegacy(legacy, 'another-salt'), isNull);
```

复现很费劲：连续 25 次全量、30 次单文件都没有稳定触发。

## 二、根因（不是测试写得松）

旧格式是 **AES-CBC + PKCS7 padding，没有认证标签**。用错误的盐解密时，
末尾的 padding 有约 1/256 的概率「碰巧」通过校验，于是 `decryptLegacy`
返回一段**乱码而不是 null**。

确定性实测（5000 次）：

| 场景 | 结果 |
|---|---|
| 错盐解密（裸 `decryptLegacy`） | **泄漏 17 次**（0.34%），每次都返回 40~46 字符的乱码 |
| 错盐解密（加形态校验后） | **0 次** |
| 正确盐解密 | **5000/5000 成功**（修复没有误杀） |

解出的乱码长这样（`codeUnits`）：大量 `U+FFFD`（65533）与控制字符，不是合法 JSON。

## 三、为什么这不只是"测试变红"

两个调用方都会**把解出的旧数据按新格式重新加密写回**（懒迁移）：

- `account_store._decodeValue` → `loadSession` 迁移
- `remote_storage_store` → `needsMigration`

一旦认了乱码，就会把用户**真实凭据覆盖成垃圾**。这比"测试偶发红"严重得多。

## 四、修法：按字段语义校验，不在解码层统一套 JSON

新增 `LocalSecretCodec.decryptLegacyJson()`（JSON 容器校验），用于远程存储；
账号侧则把校验下沉到调用方，按字段分：

| 字段 | 校验 | 理由 |
|---|---|---|
| `userJson` | 必须 JSON 对象 | 它本来就是 JSON |
| `token` | 非空 + 无控制字符 | **它是纯文本**，套 JSON 会误杀 |
| 远程存储 | JSON 容器（对象或数组） | 它是账号数组 |

### 一个当场被抓住的错误

第一版我在解码层统一加了 JSON 校验，全量跑立刻红了两条既有测试：

```
account_store_crypto_test: 旧格式凭据（固定盐 CBC）：能读出会话，并自动迁移为新格式
account_store_crypto_test: 旧格式但密钥材料已被清掉：旧密文仍可读（兼容分支不依赖新密钥）
```

因为 token 是 `'legacy-token'` 这种纯文本，JSON 校验把它拒了 —— 等于所有老用户
升级后被登出。**那两条测试正是为这件事存在的**，这次轮到它们救了我。

## 五、验证

| 项 | 结果 |
|---|---|
| `flutter analyze` | **10 issues**（与基线一致） |
| 全量测试 | **4610 通过 / 3 跳过 / 0 失败** |
| 新增回归锁 | 3 条：错盐批量不许返回内容、token 形态挡得住乱码、非 JSON 明文一律拒绝 |
| 确定性验证 | 错盐 5000 次泄漏 17 → 0；正确盐 5000/5000 |

## 七、教训（写给以后）

1. **"偶发失败的测试"值得当成线索而不是噪音。** 这次它指向的是一段没有认证的
   加密路径，以及一条会覆盖用户凭据的迁移逻辑。
2. **概率性断言要用确定性验证收口。** 25 次跑不出来不代表没问题——写一个 5000 次
   循环的探针，10 秒就拿到了 17/5000 的硬证据。
3. **通用的加解密层不该假设明文形态。** 同一个存储里既可能有 JSON 也可能有纯文本，
   把校验硬塞进解码层，代价是老用户被登出。
