## 二、真实问题（按严重度）

### P1-1 集名截断：`第04…` / `第08…`

**截图实证**：第 4 列第 1、2 行被截断成「第04…」「第08…」，而**同一列的第 12、16 集完整**。

**这排除了"格子太窄"** —— 同列同宽。真正原因是：**集名来自片源的 `ep.name` 原样透传**
（`detail_play_parser.dart:33`），站点给的名字长度完全不可控。有的叫「第04集」，
有的叫「第04集 高清」「第4集-中字」。

**现在的处理**：`maxLines: 1` + `ellipsis`，只能说"看不全"。

**为什么这是问题**：用户点集数是看**序号**，而现在序号可能被截掉（「第04…」还能猜，
若站点给「04 高清版」就完全看不出是第几集）。

**改法**（两条，建议都做）：
1. **从原始名里抽序号**做**主显示**，原名保留为辅（见设计稿）；
2. 抽不出序号时，允许两行（`maxLines: 2`），并降字号到 12。

### P1-2 线路 chip 与剧集区**视觉权重失衡**

截图里线路 chip（`liangzi` / `lzm3u8`）是**大胶囊 + 渐变色（选中）**，
而剧集格子是**小方块 + 浅灰**。但线路通常只有 2-4 个，剧集有 28 个 ——
**次要信息（线路）比主要信息（选集）更抢眼**。

**改法**：线路 chip 降到与剧集格子同一视觉层级（浅底 + 描边，选中用橙色描边而非渐变填充），
把"强烈的橙色"留给**当前正在看的这一集**。

### P1-3 「正在播放 · 第01集」与橙色胶囊重复

截图里同时有：
- 标题下副标题：「正在播放 · 第01集」
- 网格里第 01 集：橙色渐变高亮

同一件事说了两遍。已有测试只处理了**单片**的情况（`isSingleEpisode` 时不显示），
多集时仍重复。

**改法**：副标题改成更有用的信息 —— **共几集 / 当前线路 / 是否已看**，
或者干脆去掉，只在"跨段跳转"时用那一行显示「当前位置：第 N 集」。

### P2-1 「展开全部 (28)」但**只显示了 24 集**

截图：一屏显示 24 个格子，按钮写「展开全部 (28)」。
但代码里 `collapsedLimit = 24`、`needCollapse = indices.length > 24` ——
**28 集时收起状态就是 24 集，展开才是 28**。文案没错，但用户会疑惑
"为什么展开全部是 28，现在只看到 24"。

**改法**：按钮文案改成「展开剩余 4 集」，比「展开全部 (28)」准确。

### P2-2 「共 28 集」与「展开全部 (28)」两个 28 并列

截图里这两处挨得很近。前者是总数，后者是展开范围 —— **同一个数字出现两次**容易误读。

### P2-3 播放器占了将近 1/4 屏，但**没有"收起播放器"**

截图：播放器 + 上下留白约占 700/2800 ≈ 25%。看剧集时用户想快速切集，
播放器占着大块空间意义不大（尤其在竖屏浏览选集时）。

**改法**：加一个"收起播放器"手势/按钮，收起成一条 60dp 的迷你条（标题 + 播放/暂停 + 进度）。
这个改动收益很大，但要动布局，建议单独一版。

### P3 小问题

- **线路名 `lzm3u8` 是技术名**：站点原样给的名字。建议在名字后面加人数/清晰度时
  才显示原名，否则显示「线路 1」「线路 2」更易读（但会丢失"这条线是 lzm3u8"的信息，
  **需要你拍板**）。
- 选集面板里 `第04…` 与 `第4集` 混排：站点数据不统一，序号抽取能统一这个。

### P3-1 只有 2 条线路，却仍然绑着横向滑动手势

`_buildLineChips` 与分段跳转都用 `SingleChildScrollView(scrollDirection: horizontal,
physics: BouncingScrollPhysics())`。内容不超出时它**本来不该响应横滑**，
但 `BouncingScrollPhysics` 会让它在边界也回弹、并吃掉这次手势——
表现是"想上下滑页面，手指落在 chip 上却轻微回弹一下"。

**改法**：内容宽 <= 容器宽时把 `physics` 换成 `NeverScrollableScrollPhysics()`。
用 `LayoutBuilder` 量一次即可。收益小但很廉价。

## 三、UI 重设计稿

### 设计目标

1. **序号优先**：用户找的是"第几集"，不是"这一集的完整标题"
2. **信息分层**：播放器 > 选集 > 线路（线路是次要的，应退到后面）
3. **一屏多给**：减少重复文案，把空间还给选集

### 线框图

```
┌─────────────────────────────────────┐
│ ←   天才，女友            ♡  ⟳  ⤓   │  ← 顶部：标题 + 三个动作
│     量子资源 · 共28集 · 更新至28集    │  ← 副标题改为「有用信息」，不是重复状态
├─────────────────────────────────────┤
│                                     │
│          [ 播放器 16:9 ]             │
│                                     │
│  00:06 ▬▬▬●─────────────── 50:12    │
│  ⏮   ⏸   ⏭              ⛶  ⌄收起   │  ← 新增「收起」：看选集时不占地方
├─────────────────────────────────────┤
│ 选集                        共 28 集 │  ← 标题 + 总数（合并，不再重复）
│ ┌───────────────────────────────┐   │
│ │ [01] [02] [03] [04] [05] [06] │   │  ← 序号大、集名小；6 列（原 4 列）
│ │  ●                            │   │     ← 当前集：橙色描边 + 淡底
│ │ [07] [08] [09] [10] [11] [12] │   │
│ │  ...                          │   │
│ └───────────────────────────────┘   │
│        展开剩余 4 集 ⌄               │  ← 文案改准确
├─────────────────────────────────────┤
│ 线路  ▸ 线路1  ▸ 线路2  ▸ 线路3      │  ← 移到选集下面，样式降级
│        (lzm3u8)   (liangzi)         │     ← 技术名作副注，不占主位
└─────────────────────────────────────┘
```

### 关键改动

| # | 改动 | 理由 |
|---|---|---|
| 1 | **网格 4 列 → 6 列**，格内改「序号大 + 集名小」 | 一屏从 24 集变 36 集，且序号永远可见 |
| 2 | 当前集用**橙色描边 + 淡底**，不用渐变填充 | 填充太重，且和线路 chip 的选中态撞了 |
| 3 | 线路行**移到选集下面** | 线路是次要信息（2-4 个），不该抢在 28 集前面 |
| 4 | 线路 chip **降级为浅底 + 描边** | 与选集格子同层级，选中的强色只留给"当前集" |
| 5 | 「正在播放 · X」→「量子资源 · 共28集 · 更新至28集」 | 去掉与橙色胶囊的重复，换成用户真正想知道的信息 |
| 6 | 「展开全部 (28)」→「展开剩余 4 集」 | 文案与实际行为一致 |
| 7 | 播放器加「收起」 | 浏览选集时把空间还给列表 |

### 序号抽取规则（P1-1 的核心）

```
原始集名                      → 主显示   副显示
第04集                        → 04        —
第04集 高清                   → 04       高清
第4集-中字                    → 04       中字
天才女友 第04集               → 04       天才女友
04                            → 04       —
无编号的任何名字               → 原名（两行）
```

实现要点：
- 用正则抓第一个连续数字段（`(\d{1,4})`），**不抓年份**（4 位数且 > 1900 的跳过）
- 抽到就把数字**补零成 2 位**（第4集 与 第04集 统一成 04）
- 抽不到 → 退回原行为（但允许 2 行）

## 五、需要你拍板

1. **线路名怎么显示**？`lzm3u8` / `liangzi` 是站点技术名。
   - A：原样显示（信息全，但难读）

## 八、第六轮（2026-10-19）：两个"上一轮引入/暴露"的缺陷

> 触发：接续评估"下一步优化"时，用深色档截图与"收起后"截图**逐张复核**，
> 抓到两个此前没人报的缺陷。都不是审美问题，是对比度/交互自相矛盾。

### 缺陷 1：「收起播放器」与「展开」同屏并存（第五轮引入）

- **现象**：点「收起播放器」后，播放器位置换成迷你条（右侧写「展开」），
  但下方工具行**仍然画着「收起播放器」** —— 同一屏两个反向开关，
  且下面那个点了没有反应（播放器已经收起了）。
- **成因**：第五轮把收起入口并入 `_buildPlayerToolsRow` 时，
  只处理了"展开态要显示"，没处理"收起态要隐藏"。
- **修法**：`_buildPlayerToolsRow` 里的开关挂到 `if (!_playerCollapsed)` 下；
  收起态该行只保留线路（线路在收起后仍要能换）。
- **护栏**：`video_player_collapse_test.dart` 新增
  「同一屏不许出现两个反向开关」，断言开关落在 `!_playerCollapsed` 分支内。

### 缺陷 2：深色模式下「选集 / 影片资料」标题几乎看不见（既有缺陷，非本轮引入）

- **现象**：深色档下「选集」标题几乎整块消失。
- **实测**：`AppSectionTitle` 写死 `AppTokens.inkDark`（常量近黑 `0xFF111827`），
  压在深色卡底 `#171B22` 上，WCAG 对比度 **1.03:1**（正文要求 ≥ 4.5）。
  换成 `AppTokens.textPrimary` 后是 **14.6:1**。
- **波及**：`AppSectionTitle`（选集 / 影片资料 / 剧情简介三处共用）+
  `DetailInfoCard` 的资料值列，同一写法。
- **修法**：两处改 `AppTokens.textPrimary`（跟随深浅）。
- **为什么之前的测试没抓到**：`dark_theme_test.dart` 原有的对比度用例只检查
  **token 两两搭配**（`textPrimary` vs `surface` 等），而这里是**组件把常量色
  当正文色用** —— token 本身没错，错在取用方式。
- **护栏**：新增用例「正文/标题色不许写死 inkDark」，并先断言
  `inkDark` vs 深色 `surface` 的对比度确实 < 1.2（证明这条不是洁癖）。

## 九、第七轮（2026-10-19）：去重 + 已看标记（P1 / P2 / P3）

> 承接上一节，按「先低风险去重、再上新能力」的顺序做完三档。
> 每档都配了渲染截图与护栏，不靠肉眼判断。

### P1 · 一屏三遍的同一集数

实测：`全 24 集`（头部）、`当前线路 24 集`（选集卡标题下）、`共 24 集`（剧集行）
三处取值完全相同（都是当前线路的 `episodes.length`）。

- **改法**：删掉选集卡标题下那行副标题，只留 `共 N 集`
  （它和"正序"同一行，是工具栏，位置最自然）。
- **副作用**：卡片少了约 20dp，选集整体上移。
- **护栏**：`video_detail_layout_test.dart` 两条断言改为锁"结果"
  （标题下不许再出现 `正在播放 ·` 与 `当前线路`），而不是锁某个分支存在。

### P2 · 同一句续播提示说两遍（并顺带修好"关闭点了没反应"）

实测（渲染断言）：`initialPosition > 0` 时，同一句
「已为你恢复到上次播放位置：00:43」同时出现在
① SnackBar（2 秒后消失、盖住底部）② 选集卡内的黄色提示条。两者读同一个字段。

- **改法**：删掉 SnackBar 那条通道，只留卡内提示条（可关闭、不遮挡、更持久）。
  `_VideoDetailViewState` 里那个只负责弹 SnackBar 的 controller 监听器一并删除
  （页面本来就 `watch` 着 controller，不需要手工订阅）。
- **顺带发现的真 bug**：`consumeResumeMessage()` 只把字段置空、**没有
  `notifyListeners()`**，所以点提示条上的 × 界面不刷新。
  之前被 SnackBar 通道掩盖（那里随后常有别的 notify 顺手刷了界面）。
  已补 `notifyListeners()`，并加了"点关闭后提示条消失"的用例。
- **护栏**：新增 `video_detail_resume_notice_test.dart`（两条：
  不弹 SnackBar 且 3 秒后仍在；点 × 后消失）。

### P3 · 已看剧集标记

追到第 18 集再进来时，24 个格子长得一样，只有橙色描边能认出"当前"。

- **判定逻辑**：新增 `lib/video/pages/detail/watched_episodes.dart`（纯函数）。
  三条判据：同一部片（`vodId`）、同一集（`episodeUrl` 归一化，去 query/fragment）、
  真看过（进度 ≥ 1 分钟）。不按 `sourceId` 过滤 —— 换源续播是既有能力。
- **视觉**：看过的格子 = 序号左侧一颗 4dp 圆点（`success` 色）+ 序号字重降一档；
  **当前集优先**，既是当前集又看过时不加绿点，避免双强调。
- **接线**：`_watchedKeysFor()` 用 `context.watch<HistoryController>()`，
