## 二、组 1：低风险小改动（建议本轮，一版收口）

### A. 「漫画收藏」指向真页面，删掉那句假话

- **现状**：`builtin_plugin_catalog.dart:236`（inline Scaffold），假话在 `:249`。
  真页面 `ComicLibraryPage` 在 `warehouse_tab.dart:732` 被正常使用。
- **机制**：入口与实现脱节 —— 用户点漫画区唯一入口，看到的是一句"还没做"，而我们其实做了。
- **改动**：onTap 改为 push `ComicLibraryPage`；顺带在路由表注册 `comic_library` / `openComicLibrary`
  （与 `builtin_plugin_pages.dart` 里其它页同形状）。
- **收益**：漫画区从"假入口"变成真入口；消除一句对用户不实的文案。
- **成本**：约 0.5 小时。**要发版**。
- **验收**：单测断言该条目的 onTap 打开的是 `ComicLibraryPage`（而不是内联 Scaffold）；
  真机点一次进入漫画库。控制组：小说/影视那两个入口行为不变。

### B. 备份健康看板：把刚演练过的事变成"看得见"

- **现状**：备份齐全且本轮已演练过还原（state / `app.db` / release tar 三份都能还原），
  但**用户看不到**：监控页只有主机指标，没有"最近一次备份是什么时候、多大、有没有通过校验"。
- **机制**：数据面已有形状（采集脚本 → 边缘机静态 `hosts.json` → App 只读消费），
  缺的只是往快照里加字段。
- **改动**：`tool/gen_hosts_json.py` 增加 `backup` 段：每台机器最新备份文件的时间/大小/
  是否可解压校验（`gzip -t` 或 sqlite `integrity_check`，取轻量那个）；App 监控页加一行卡片。
- **收益**：备份从"我说有"变成"你看得见"；出问题时第一眼能判断是不是备份断了。
- **成本**：约 0.5 天。**要发版**（App 侧显示）。零新协议、零新鉴权。
- **验收**：快照里字段非空且与机器上 `ls -l /var/backups/...` 对得上；App 显示"最新备份 09-27 03:20 · 校验通过"；
  把某台的备份目录临时改名（负路径）→ 显示"没找到备份"而不是空白。

### C. 恢复演练做成哨兵（服务端，零 App 改动）

- **现状**：本次演练是手工做的，之后无人再验 —— 备份"能不能还原"会随时间漂。
- **改动**：把演练写成一个脚本 + cron（每月一次）：还原到临时目录、校验、删临时产物、结果写日志
  `/var/log/backup-drill.log`；失败则复用现成的飞书投递（`box-ops-alert` 那套）报警。
- **收益**：一次性动作 → 常态护栏。
- **成本**：约 0.5 天，**不发版**。告警必须留痕（本仓库已有教训：不留痕的告警等于没有）。
- **验收**：手动跑一次成功；把某份备份故意改坏 → 报警真的发出来（负路径）。

### D. 网络诊断四项改并发

- **现状**：串行，最坏 32 秒（见事实基线 3）。
- **改动**：`runAll` 改成四项并发（`Future.wait`），仍然逐项回调、逐项超时。
- **收益**：最坏等待 32 秒 → 8 秒；这也是唯一一处能让这个新插件"体感明显变好"的地方。
- **成本**：约 0.5 小时。**要发版**。
- **验收**：单测断言四项的完成顺序不再固定、且总耗时 ≈ 最大单项耗时（用假传输层加延迟）；
  失败项仍然只影响自己。

### E. 网页源码获取（「开发工具」分类里最后一条未接线）

- **现状**：`tool_catalog.dart` 「开发工具」只剩这 1 项未接线；`html` 依赖已在 `pubspec.yaml`。
- **改动**：纯客户端拉取 + 简单格式化/源码视图（不引入新依赖）。
- **收益**：开发工具分类收官。
- **成本**：约 0.5 天。**要发版**。风险：大页面要限制字节数并说清截断。
- **验收**：能取到源码、超时/失败给原因、超大页面按上限截断并显示"已截断"。

## 八、组 1 实施记录（2026-09-27，1.20.59/316）

五项全部落地。下面每条只写"事实 + 证据"，包括做错又改回来的部分。

### A. 「漫画收藏」指向真页面

- `builtin_plugin_catalog.dart` 的 `builtin_comic_shelf.onTap` 不再自造 inline 占位页，
  改为经路由表打开 `ComicLibraryPage`；路由表新增 `comic_library` / `openComicLibrary` 两个 code。
- 新增回归锁 `test/plugin_manager/builtin_comic_entry_test.dart`：① 点入口必须进
  `ComicLibraryPage`，且「将在后续版本上线」这句**必须找不到**；② 两个路由 code 都注册上了。
- 结果：2 用例通过。全仓扫描确认这类 inline 假页面**只此一处**。

### B. 备份健康看板

- **采集侧**（`tool/gen_hosts_json.py`，已部署到 175 `/opt/ops-monitor/`）：
  新增 `backup` 段，按「文件名去掉时间戳」把备份归并成类，每类只报最新一份的
  时间/大小/多少小时前 + 服务端判的 `stale`（>36h）。隐藏文件与无时间戳的标记文件
  （`.last_release_fingerprint`）不算备份，不列出来充数。
- **为什么不在采集里做校验**：release 备份单份 500MB+，而采集是每 2 分钟一次 ——
  每 2 分钟 `gzip -t` 一个 500MB 文件是不现实的。所以采集只报元数据，**校验结论取自
  演练脚本的落盘结果**（没有就报 null，App 显示"还没演练过"，不冒充"已校验"）。
- **App 侧**：`host_models.dart` 加 `BackupFamily` / `BackupDirHealth`（含 `hasProblem`）、
  `HostEntry.backup`；`host_tab.dart` 在机器卡里多一段「备份 · <目录>」，逐类一行 + 演练结论一行，
  有情况时目录标题用告警色、过期那行带 ⚠。**老快照没有这个字段 → 整段不显示**（缺数据 ≠ 有问题）。
- 用例 8 条（模型 5 + 界面 3），含两条控制组：老快照不显示备份段、没演练过不冒充已校验。
- 线上验证：`hosts.json`（37165B，已推到边缘机）里 hpa888 报了 2 个目录 4 类备份，
  175 报 0 个（它本来就没有备份目录，如实报空）。

### C. 恢复演练做成月度哨兵

- 新增 `hpa888:/usr/local/sbin/backup-drill.sh`，cron `/etc/cron.d/box-backup-drill`（每月 1 日 04:00）。
  每类备份取最新一份**真的还原一次**：state 走 `gzip -t` + JSON 真解析（报 accounts/quotas
  条数）、图集 tar 列成员数、`app.db` 拷出来 `PRAGMA integrity_check` + 查 `app_release` 行数、
  release tar 列成员并抽一个 APK 过一遍字节数。结论写 `/var/lib/box-backup-health.json`（B 会读），
  失败才发飞书（复用 `hermes send --to feishu`），每次留痕 `/var/log/backup-drill.log`。
- 负路径自检（`--self-test`）：喂它两份**故意做坏**的备份（截断的 gzip / 伪造的 sqlite），
  要求都被查出来；同时给一份好备份做正向对照。实测：两项都查出来了，好备份通过 ✅。
- **实施中抓到自己的一个静默失败**：首次真跑四项校验全过、脚本 `exit 0`，但健康文件**根本没写出来**
  —— cron/ssh 的 `LANG` 是 C 时，heredoc 里的中文源码让 python 直接 SyntaxError，
  而脚本没检查落盘结果就报成功。修法：`PYTHONUTF8=1` 跑落盘，**并回读校验**
  （写不出来或解析不了就计入失败、发告警），把"看不见的失败"变成"会响的失败"。
- 实测结果（真跑）：state 还原出 accounts 5 / quotas 7；图集 19 个成员；DB `app_release` 146 行；
  release tar 41 个成员（含历史 APK）。

### D. 网络诊断四项改并发

- `NetDiagProbe.runAll` 改为四项并发（`Future.wait`）：每项一出结果就回调（回调顺序＝完成顺序，
  不固定），返回列表按检测项固定顺序排好（便于复制文本与断言稳定）。
- 界面相应改成**固定四行占位**：还在跑的那行转圈写「检测中…」，**跑完还没有结论的行明说
  「这一项没有结论（异常）」** —— 不允许"永远转圈"（那正是这个插件要消灭的东西）。
- 用例：+2 条（延迟假传输层证明总耗时≈最慢一项而非四项之和；回调顺序＝完成顺序），
  页面 +1 条（并发时四行占位、回来一个填一个）。网络诊断用例合计 **34 条**通过。
- 顺带修掉一个自己引入的 bug：`List<T> _results = const [];` 上调 `.clear()` 会抛
  `UnsupportedError`（表现为"结果根本没渲染"）。

### E. 网页源码获取（「开发工具」最后一条未接线）

- 新增 `ToolTarget` 子类 `SourceFetchToolTarget`（与 `WebToolTarget` 的区别写在注释里：
  那个是"打开页面给人看"，这个是拿服务端第一手文本；也不是 `LocalToolTarget` —— 它要联网），
  目录表接线 + 派发分支 + 图标各一处。
- 新页面 `lib/features/tools/presentation/source_fetch_page.dart`：输入网址 → 显示
  「HTTP 状态 / 大小 / 类型 / 最终地址」+ 源码文本（可复制），超过 200KB **明说已截断**；
  失败**写出原因**（超时/DNS/拒绝/TLS 握手），并可一键「用内置浏览器打开」对照渲染后的样子。
  界面上直说：动态页面的内容由 JS 生成，这里看到的多是空壳。
- 取数走接缝 `SourceFetch`（真机 `IoSourceFetch`），单测注入假实现不联网：
  **5 条**单测（认不出的地址不发请求、200、截断、失败给原因、404 标出但仍给源码）+
  **2 条 live**（真连自家发布接口拿到 200 与真实 JSON；反面：解析不了的域名给出可读原因）。
